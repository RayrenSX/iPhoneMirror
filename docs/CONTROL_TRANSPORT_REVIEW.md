# 有线与无线控制全链路复审（2026-10-07）

本轮覆盖主程序入口与目标绑定、桥接进程、USB/Network usbmux 与 RemotePairing 发现、
DDI 共用准备流程、隧道/RSD 身份、HID/Indigo 输入、空闲检查、断线恢复、停止和再次启动。
此前 DDI 下载、签名、挂载及来源回退的修复记录见 `DDI_STARTUP_REPAIR.md`。

## 本轮发现及修复

| 环节 | 原问题 | 修复后行为 |
|---|---|---|
| 有线传输 | USB CoreDeviceProxy 缺失时转用局域网，仍上报为有线 | 保持所选传输，明确提示服务不可用及切换无线的操作建议 |
| 无线入口 | Apple Network usbmux 不可用或握手卡住时，未进入独立的 RemotePairing 路径 | 初始握手限时 15 秒；无线入口可继续检查已保存的 RemotePairing 凭据 |
| 无线发现 | 串行验证地址；首地址卡住可遮挡其他可用网卡，取消时遗留部分连接 | 去重并发验证发现地址；逐个尝试可用隧道；取消时关闭未交付连接 |
| 无线清理 | RemotePairing 内部等待 writer 关闭可能拖住取消 | 关闭限时，异常时中止底层 writer；已建立会话的故障交回主程序恢复 |
| 设备身份 | RSD 连接后没有再次核对实际设备身份 | 开启 HID 前核对 RSD UDID；配对记录匹配统一大小写和连字符 |
| 可选配对 | 每个子步骤单独计时，可能拖延有线启动 | 可选无线配对的所有步骤共享 30 秒预算，失败后继续有线流程 |
| 主程序启停 | 重复停止、停止期间重启及旧输出回调存在竞态 | 启停互斥；停止取消待启动操作；旧进程 stdout/stderr 不得修改新会话 |
| 启动错误 | Stop 导致的 ready 取消被误判为启动超时 | 区分取消和期限到达；设备握手超时补充四语言提示 |
| 跨进程输入 | 新子进程的协议 generation 重置为 1，可能接收上次会话的旧输入 | 主程序使用单调递增的会话标识，协议保留子进程编号；剪贴板请求同步采用此分离 |
| 输入收尾 | 媒体 HID 关闭后才释放按键/触点；按钮服务部分打开时遗漏清理 | 在 HID 和认证媒体仍打开时释放输入；释放可能按下的按钮并关闭部分服务 |
| 有线恢复结果 | Start 返回后立即断开时仍可能标记恢复成功 | 重新检查 bridge readiness、当前所有者及停止状态后才恢复输入路由 |
