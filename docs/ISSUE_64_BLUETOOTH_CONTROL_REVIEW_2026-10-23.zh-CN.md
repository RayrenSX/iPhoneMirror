# Issue #64：蓝牙输入切换与独立窗口拖动

问题链接：<https://github.com/RayrenSX/iPhoneMirror/issues/64>。

## 反馈与证据

报告最初涉及 v1.8.3 下蓝牙控制卡死，以及 iPhone19,2 / iOS 27.0.1 的 USB、Wi-Fi 控制不可用。用户随后确认 v1.8.5-pre3 已改善闪退，剩余反馈为 F9 切换异常、一次断连、独立窗口不能拖动及反复出现连接提示。

读取了 issue 正文、全部评论，以及 GitHub 附件 application.log 和 reverse-control.log。补充网盘压缩包未成功取得：蓝奏下载返回 JavaScript 验证页，迅雷要求登录。未读取压缩包内的视频，未将下载验证页当成 ZIP 分析。

application.log 中多次出现 `bluetooth_control_stop_begin` → 约 2 秒后 `bluetooth_control_stop_complete` → 下一次按键 `bluetooth_control_start_begin` 的序列。`show_notice=False` 时仍会再次建立蓝牙控制并触发连接状态流程，说明一次性引导策略不能消除每次重新连接的状态弹窗。

日志另有一条 AirPlay 断开：2026-10-20 00:21:20（北京时间）蓝牙停止完成，00:21:47 检测到无线画面停滞并尝试刷新，00:22:47 记录 `AirPlay_disconnected`。这些记录不能证明 F9 导致了 AirPlay 断开。

## 确认的代码问题

1. `ToggleBluetoothControlAsync` 原来每次退出都调用 `DisableBluetoothControlAsync`，释放鼠标后仍需等待 BLE 报告释放和广告停止。期间再次按键被启动条件拒绝；后续开启重新经历连接检查、校准和倒计时。
2. 快捷键处理原来在模型撤销输入前调用 `ClearBluetoothControlInputState`，清理过程可能根据尚未关闭的模型状态短暂重新注册 Raw Input；附件也出现过先关闭、随即重新开启、再关闭注册的序列。
3. `NativePreviewWindow.EnableReverseControl` 无条件通过 `EnsureFixedWindow` 持久设置 `_isFixed`。退出蓝牙后，该设置没有恢复，`WM_NCHITTEST` 继续返回客户区，不能通过画面拖动窗口。
4. 仅释放主预览的鼠标捕获不能清除独立 HWND 保留的捕获状态。

## 本次改动

- 已建立蓝牙连接后，F9 在暂停与恢复输入之间切换，保留原有 GATT 会话、设备目标及校准状态。暂停立即释放本机输入、光标限制和鼠标捕获，异步释放手机端按键；恢复不重复创建连接提示窗口。
- 串行处理快速切换，恢复必须等待上一轮报告释放。使用输入会话代次拒绝旧会话排队按键；断连、未完成校准、传输失败时拒绝恢复。首次连接的倒计时仍有效，迟到倒计时不会解除用户的暂停。
- 显式停止、关闭窗口、结束会话及切换传输仍使用真正的蓝牙关闭流程。
- 独立窗口只在输入启用期间临时按客户区处理，不再因启动蓝牙改变用户的固定窗口设置。暂停后恢复拖动；用户手动固定的窗口继续固定。
- 清理时释放对应独立 HWND 的鼠标捕获。恢复快捷键会激活对应控制窗口。
- 更新简体、繁体、香港繁体和英文提示，以及使用指南。

## 复审修复

首次复审发现三处需要修复的问题，本轮均已处理：

1. **暂停后切换键盘模式可能恢复输入。** 蓝牙键盘路由现在要求输入已开放，发送时再次检查暂停状态和输入代次。暂停、恢复和连接生命周期变化都会撤销旧代次。正常失焦的空报告释放仍通过原来的有效会话发送；暂停和停止则由统一释放流程负责。
2. **尽力释放不能用于保留连接的暂停。** 服务新增可检查结果的 `PauseInputAsync`，保持输入队列关闭，只有必要的释放报告全部成功才允许保留连接。鼠标报告必须成功；会话曾提交过的键盘、consumer 和 navigation 报告也必须成功，不能把缓存中的零值当作手机已经松键的证据。未使用的可选报告无需订阅。发送失败、异常或超时后模型关闭连接兜底，并撤销排队的恢复操作；后续开启重新走连接检查。
3. **选择 B 后 F9 可能恢复 A。** 所有切换按键在同一个门闩内核对请求目标；目标变化时停止旧连接，再走新目标的启用流程。主窗口也会为新目标显示连接状态。只有同一目标才直接恢复输入。

第二轮复核同时补充了释放报告的目标设备、BLE 客户端和路由代次校验，防止迟到释放发往替换后的客户端。

快捷键恢复前也会尝试激活对应控制窗口，并在等待释放结束后再次核对前台窗口；Windows 拒绝激活或等待期间焦点离开时保持暂停，避免隐藏、限制其他窗口中的桌面光标。

`--bluetooth-input-toggle` 新增覆盖：

- 暂停后 Mapping → Direct 的真实键盘路由事件留给 Windows；旧键盘路由跨暂停/恢复持续失效，新路由可以正常输入。
- 故障注入仅替换 GATT 发送结果，生产队列、释放结果判断和超时流程照常运行；逐项验证鼠标、键盘、consumer、navigation 释放失败的断连兜底。
- 缓存为零但此前已提交键盘报告的情形仍检查释放；未使用的可选报告不影响正常暂停。
- 释放超时、迟到回调、超时期间排队恢复，以及 BLE 客户端替换时的旧报告拒绝。
- 恢复排队期间焦点失效时保持暂停，不开启手机输入。
- 使用未替换的生产发送方法触发目标锁超时，确认关闭连接。
- 在 A 暂停后请求 B，确认停止 A 并进入 B 的启动流程；测试中 B 无可用会话，因此通过 B 的启动失败状态验收，不假装完成真实蓝牙连接。

正常恢复仍不重复弹出状态窗口；故障关闭后重新连接、或切换到其他设备时需要重新检查并显示连接状态。

复审修复后的构建与验证：

- 运行时测试项目构建通过，无编译警告或错误。
- `--bluetooth-input-toggle` 全部通过，包含上述三处问题及报告类型记录、BLE 客户端替换、失败与迟到操作的回归。
- `--interaction-regression` 通过，包含 watchdog、取消、迟到完成、回调隔离和并发释放。
- `--keyboard-router` 和 `--keyboard-focus` 通过，包含 USB/无线输入、文本输入、多设备归属与蓝牙队列校验。
- 本轮 `--preview-pointer` 的蓝牙独立窗口移动、按钮、滚轮及焦点校验通过；随后 USB 原生预览测试因 Windows 拒绝激活测试 HWND 而中断，报错为 `Test could not acquire foreground`。不能将该次完整原生鼠标套件记为通过；此失败发生在输入测试窗口的激活前置条件，尚无产品输入逻辑失败证据。

## 后续两项 P1 的修复与复核

后续审查确认的鼠标跨暂停恢复和通知结果误判已修复：

- `FlushControlPointerAsync` 在取出输入前捕获输入会话与焦点代次。ViewModel 在调用服务前绑定暂停代次，服务在进入输入准入前绑定 pump/路由代次；鼠标移动、按钮、滚轮及重试报告均保留该校验，实际通知发送前再次检查。外部焦点与所有权校验在 producer 锁外执行，避免锁顺序反转。
- 鼠标和键盘/consumer/navigation 两条 WinRT 通知路径均检查 `GattClientNotificationResult`。仅 `Status=Success`、发送字节数完整且没有协议错误才算成功；失败进入现有传输恢复流程，暂停释放失败则关闭连接兜底。
- 失焦清理先丢弃旧移动和滚轮，再发送同一输入会话的空释放报告。空释放不依赖当前前台窗口，仍受暂停代次约束，避免留下手机端长按，也避免迟到释放清掉恢复后的新按键。

- `--bluetooth-input-toggle` 通过：服务准入被阻塞跨暂停/恢复；生产后台 flush 的旧点击/移动拒绝及新鼠标输入成功；队列中的移动/按钮/滚轮在发送等待后校验；旧来源快照失效；失焦空报告释放；通知完成但状态失败、短写入和协议错误的断连兜底。

提交后的进一步复核发现：保留 BLE 路由时，服务层键盘/consumer/navigation 生产者及系统快捷键的延迟松键只绑定路由代次，可能跨暂停/恢复进入新的输入会话。新增离线屏障测试在修复前稳定失败于 `HID 1 producer crossed pause/resume`。`CaptureReportSessionGuard` 现同时绑定报告 pump 的输入代次，覆盖准入前挂起的生产者与快捷键 `finally` 中的释放报告。新增用例验证三类旧报告和迟到松键均被丢弃，恢复后的新输入仍正常；该用例同样由无桌面 CI 入口执行。

上述测试均为离线验证，没有向真实手机发送输入；不替代 iPhone19,2 / iOS 27.0.1 的实机长期稳定性验证。
