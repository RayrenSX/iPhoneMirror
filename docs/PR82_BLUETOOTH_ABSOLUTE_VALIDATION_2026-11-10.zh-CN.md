## 取消固定后无法移动的补充修复

用户发现：独立窗口开启实验模式蓝牙后，取消固定仍不能移动。原生窗口的 `AllowsControlInput` 仅对有线/无线触控检查固定状态，实验蓝牙一直被视为可接收输入，导致 `WM_NCHITTEST` 始终返回 HTCLIENT。

现将实验蓝牙与有线/无线的空间控制规则统一：新会话启动时准备固定的窗口输入区域；取消固定会立即释放指针和键盘状态，停止设备输入，恢复 HTCAPTION 和边缘缩放命中。重新固定或进入全屏恢复输入，退出全屏回到未固定状态时再次释放。相对蓝牙保留原行为。F9 暂停/恢复不会重新固定用户已取消固定的窗口。

已扩展原生窗口回归覆盖实验蓝牙、启动准备、取消固定后的中心/边缘命中、按下时取消固定的释放、屏蔽鼠标/键盘转发、全屏退出和重新固定；映射输入准入同时覆盖实验蓝牙与有线控制。日志为本地 `artifacts/pr82-unfix-context-regressions.log`、`artifacts/pr82-unfix-bluetooth-regressions.log`。

## 第二轮反馈：拖动延迟、独立窗口和主界面开关

上一轮为防止拖动突跳，将单包计数限制为 16，造成较长位移串行发送过多报告。本轮实测相对计数 32 和 48 的移动距离，确认原预测曲线在此范围仍匹配；当前上限为 48，每次按剩余距离选择计数，并移除每个子步额外 8 ms 等待。GATT 通知仍逐条确认，只在完整采样之间按原策略节流，没有并行堆积蓝牙通知。

相同测试路径的手机网页事件：旧版第一段按住移动到 up 为 232 ms，本轮为 45 ms；终点分别 `(242,355)`、`(244,356)`，目标约 `(243,356)`。这是手机端动作执行时长，不是 Windows 到手机的端到端延迟。20 个采样点、16 ms 入队间隔的连续拖动也到达 `(242,355)`。生产独立窗口真实鼠标拖动复测终点误差 1 个网页逻辑像素。

本轮独立窗口行为与有线/无线保持一致：实验模式右键显示窗口菜单，不向手机发送 Home/右键；双击切换全屏；中键仍保留快捷键入口。未启用实验模式时，相对蓝牙右键继续转发到手机，阻止窗口菜单。通过真实 Windows 右键事件确认两种模式的 menu 状态分别为 true/false；双击全屏的进入/退出和中键由原生窗口回归覆盖。

主界面蓝牙按钮改为启动/关闭连接，启动后不再因为 `CanStartBluetoothControl=false` 而永久变灰；提示语相应更新为「关闭蓝牙控制」。F9 的暂停/恢复保持原行为。真实 BLE 连接中触发主界面按钮的点击处理，确认广播停止、目标清空；该项验证控件绑定与生产点击处理，没有绕过模型直接停止服务。

新增回归覆盖较长拖动的报告预算（187.5 逻辑点不超过 5 条移动报告）、小于一逻辑点的精细移动、菜单模式切换、中键、双击全屏、按钮绑定和完整关闭。完整蓝牙/F9 失败矩阵继续覆盖。

## 用户反馈后的拖动定量补测

用户手动测试发现「一开始拖动就跳位」。此前的拖动验收只确认列表能滚动，遗漏了指针路径和终点准确度，不能代表拖动定位正确。

已复现根因：按住后的路径把每个归一化轴当成固定 1024 个相对鼠标计数；iOS 对相对计数施加非线性加速，横纵屏幕尺寸也不同。旧版第一段实际从网页 `(93,274)` 跳到 `(230,309)`，继续拖动到右边缘 `(374,554)`；同一目标应为 `(243,356)`。

当前改为按设备显示目录和实际来源宽高比换算设备逻辑点，逐步预测相对位移，单包向量长度不超过 16；保留未走完的残差。新位置样本替换旧目标，松开前完成最后位置。键盘事件可打断长路径并优先发送，随后继续未完成的松开。没有更改 HID 描述符，不需要因为本次修正重新配对。

绝对位置不能直接更新 iOS 正在进行的接触轨迹：混发试验在手机网页上出现提前 up/click，数字化仪方案未产生事件，均已撤回。相关公开实测也记录了这一限制，参见 [ghosthand 的 iOS 拖动实验](https://ghosthand.dev/docs/relative-pointer#drags-on-ios-17-and-later)。

## 最终实现

- 设置项为「蓝牙绝对位置（实验）」，默认关闭；关闭时保持原有相对鼠标与 F9 暂停/恢复逻辑。启动蓝牙控制时选择对应 HID 描述符，运行中不可切换。
- 每个新点击或滚动手势先激活相对鼠标集合，再发送绝对位置，避免重新连接或滚动后的首次点击落在旧指针位置。同一位置重新点击也刷新锚点。
- 按下与抬起按顺序保留，队列上限 64 条；溢出时丢弃积压手势并插入无位移释放，之后才开始新手势。移动仅保留最新位置。为 iOS 留出定位、按下和释放的处理间隔，避免快速点击被合并或读到下一次的位置。
- 未获确认的按下可重试，仍保留失败按下的释放清理；重试不重播旧位移。
- 混合鼠标的滚轮在这台手机上没有可靠原生响应，实验模式改用同一 BLE 链路上的短距离拖动，每次位移和时长有上限。按下起点保持在请求位置；靠边时缩短位移，低于最小拖动距离则忽略，避免变成点击。结束后释放并恢复原绝对位置；失焦、离开、预览几何变化或暂停取消剩余位移并释放。
- 滚动中途发送失败时保留独立的合成手势状态，清理只释放按键，不把下一位置当成未完成的拖动继续发送。
- 已保存蓝牙绑定的最终 HID 订阅事件可以直接完成校验，避免异步绑定枚举期间漏掉连接完成通知。

## 真机验证方式

手机连接电脑热点；测试网页运行在电脑热点网卡上，记录手机浏览器实际收到的 `pointerdown`、`pointerup`、`click`、`pointercancel` 和滚动位置。此数据是手机端观测，不是发送成功计数。

测试网页为 `tools/bluetooth_pointer_test_page.py`，沿用原五点触控网页的本地事件记录方式，增加九宫格和独立滚动区。页面通过 BLE 键盘输入网址打开。最初从 Safari 标签页总览选中测试标签时使用了一次已有 CoreDevice 触控；这只是测试准备，不计入蓝牙验证数据。之后的点击、拖拽和滚动全部通过生产 `BluetoothHidMouseService` 的 Windows BLE GATT 发送，并限定到 12 mini 的既有绑定。

主窗口与独立窗口使用 `--bluetooth-absolute-window-live` 硬件测试入口：保留生产模型的蓝牙启动、校验、前台守卫、Win32 鼠标事件处理、坐标映射和 GATT 发送。使用真实 Windows 鼠标输入，前台或目标位置不符合条件时测试失败；不伪造前台值或 GATT 成功。为了隔离投屏发现，测试固定已知设备几何，不运行视频采集，所以这是完整输入链路验证，不是整套视频采集验收。

原始截图和事件日志只保存在本地 artifacts，不纳入提交、不上传；不公开 UDID、配对记录、地址或私人屏幕内容。测试未修改手机设置。

最终复审未发现新增可复现缺陷。此结论限于上述实现、设备和覆盖范围，不能代替完整视频采集、混合 DPI 多显示器或其他设备系统的验收。

```powershell
python tools/bluetooth_pointer_test_page.py --bind <电脑局域网地址> --port 8765 --output artifacts/bluetooth-pointer-events --phone-address <手机地址>
```
