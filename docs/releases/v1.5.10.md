# iPhoneMirror v1.5.10

v1.5.10 是一次聚焦 USB 启动稳定性和 AirPlay 服务生命周期的补丁更新。它不更换驱动、不删除功能，也不取消任何现有 USB 后端或回退路径；核心变化是减少自动后台任务进入第三方 USB 内核过滤器的次数，并把确实需要访问 USB 后端的激活流程严格限制在用户明确开始有线投屏之后。

## 蓝屏转储结论

本次分析读取了 Windows 小型内存转储 `080526-21734-01.dmp`。转储记录的停止码为 `0x7F`，参数 1 为 `8`，对应 `EXCEPTION_DOUBLE_FAULT`。故障时指令位于 `nt!ExAllocateHeapPool+0x2f`，内核栈已越过 guard page，表现为 I/O 完成路径中的 DPC 栈耗尽。

蓝屏前的系统事件同时记录了 `AppleUsbFilter.dll` 的 UMDF verifier failure，随后同一 Apple USB 设备的三个接口离线。设备栈中可见 `libusb0.sys`、`AppleLowerFilter.sys`、`AppleKmdfFilter.sys` 与 `usbaapl64.sys`。转储无法单独、唯一地指定某一个责任驱动，但时间顺序与调用路径表明：应用启动后的后台精确 USB 探测很可能放大了 Apple 与 legacy USB 过滤器之间的设备生命周期竞态。

因此，本版本的防护目标不是替换用户驱动，而是避免在启动、周期刷新和设备选择期间进行没有必要的精确 USB 枚举，并使显式投屏所需的激活、重枚举、打开和恢复流程可控且串行。

## USB 稳定性保护

- 启动应用、每两秒环境刷新和切换设备时，不再初始化或枚举 USB 采集后端。
- legacy USB 运行库的自动检测改为文件存在性检查，不会仅为了显示状态而加载运行库或进入内核过滤器。
- 精确设备探测保留完整功能，但只在用户明确点击开始有线投屏后执行一次权威预检。
- USB 预检、`0x52` QuickTime 配置激活、设备重枚举、接口 claim、握手到首个媒体样本之间使用进程级串行保护，首个稳定媒体样本到达后立即释放，仍支持多设备同时投屏。
- 新会话优先沿用已有活动会话使用的 USB 后端；若目标设备不可见，原有 `libusb0`、`libusb-1` 和 UsbDk 回退顺序仍可继续尝试。
- 已知物理拓扑时只检查目标设备；未知拓扑时优先按 Product ID 缩小候选，再逐个读取 serial，命中后立即停止，不再为了生成完整列表打开全部 Apple 设备。
- QuickTime 激活后立即登记配置恢复任务。取消、打开/claim 失败、握手失败、运行异常和停止都会尝试恢复普通 USB 配置；正常关闭成功后解除备用恢复任务，避免重复发送配置恢复请求。
- 活动 USB 身份采用引用计数缓存，避免一次会话关闭时错误移除仍被另一活动句柄使用的身份。
- 主窗口和独立设备窗口增加同设备启动状态协调；拿到会话门后先复用已经创建的句柄，避免并发创建两个 native session 或重复执行 USB 预检。

## AirPlay 与网络服务

- DNS-SD 注册从可用的物理网卡中选择单一接口，优先保留上游明确请求的有效接口，并避开虚拟、隧道、回环和无组播能力的适配器。
- 多网卡场景中的多个上游注册引用现在共享一个逻辑服务租约，防止 iPhone 看到重复接收器名称。
- 释放某一个适配器引用不会提前销毁仍被其他引用使用的服务；接口所有者变化时会完成受控的注销与重新注册。
- 异步注册、取消、回调和模块卸载路径增加引用计数与回调等待保护，避免悬空上下文和重复释放。

## 功能与驱动兼容性

- 没有删除 USB Screen Capture、AirPlay、音频、截图、录制、推流、OBS 输出、虚拟摄像头、多设备或独立窗口功能。
- 没有替换、升级或静默安装新的 USB 驱动；驱动管理器与既有 `libusb-win32` 兼容路径保持不变。
- 没有改变现有用户设置格式，也没有新增第三方运行时依赖。
- 仍支持 Windows 10 1809 及以上版本和 Windows 11 x64，可直接覆盖安装 v1.5.9。

## 已知限制

- Windows 转储只能确认 double fault、DPC 栈耗尽及当时的复合 USB 过滤器栈，不能仅凭该转储唯一判定某一个第三方驱动。此版本降低了应用触发相关竞态的机会，但无法保证任何外部内核驱动永远不会发生故障。
- `libusb0` 与 `libusb-1`/UsbDk 对 Windows 物理拓扑的字符串表示仍不完全相同。本版本通过激活期串行化、活动后端优先和定向查找降低跨后端误触风险，尚未宣称跨后端位置键已经完全统一。
- 当前安装程序未使用商业 Authenticode 证书签名，Windows SmartScreen 可能显示“未知发布者”。请只从项目官方 GitHub Release 下载并核对 `SHA256SUMS.txt`。
- QuickTime Screen Capture 与兼容 AirPlay 实现并非 Apple 官方稳定接口，未来 iOS 更新仍可能需要适配。
