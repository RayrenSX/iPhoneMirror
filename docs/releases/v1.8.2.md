# iPhoneMirror v1.8.2

v1.8.2 是有线与无线投屏、反向控制和发布链路的稳定性更新。此版本统一使用维护中的 USB 桥接器，并强化横竖屏切换、键盘输入、硬件按键、快捷键和首次使用引导。

## 有线与无线投屏

- 无线投屏设置会保存到本机，后续启动和设备重连时保持已选分辨率、帧率与画面模式。
- 改进无线横屏切换期间的帧流恢复和画面状态处理，减少横竖屏变更后预览停滞的情况。
- 有线投屏的设备发现、DDI 准备、USB 通道和运行时依赖校验得到加强；无法继续时会显示明确的处理提示。
- 首次通过 USB 或无线发现设备时，应用会引导建立设备档案，便于后续连接和控制路由恢复。

## 反向控制与输入

- 有线和无线反向控制统一接入维护中的 USB 桥接器，支持鼠标触控、键盘字母数字输入、文本输入和按键释放。
- 支持音量增加、音量降低、锁定屏幕、主屏幕和 App 切换器等 iOS 硬件操作；App 切换器使用双击主屏幕的系统行为。
- 独立窗口菜单明确区分蓝牙控制、无线投屏和有线投屏；各模式按各自控制路由接收输入。
- 快捷键窗口支持分别配置控制操作，并支持用鼠标右键或中键直接设置快捷键；恢复保留的功能键限制，避免系统快捷键冲突。
- 改进横屏与竖屏下的坐标映射、鼠标捕获和拖动释放；指针移出预览区域后松开按键不会再保留触控焦点。

## 使用引导与错误处理

- 有线和无线控制启动前会显示简洁的开发者模式及设备准备提示，样式与连接等待界面保持一致。
- 反向控制失败使用统一错误窗口，清晰说明当前控制无法继续的原因和可执行操作。
- 开发者工具同步提供新增提示和诊断入口，便于定位连接、DDI、运行时和控制链路问题。

## 运行时与发布

- 应用、安装器、完整性清单和发布包统一使用 `iUsbBridge.exe` 与其运行时清单，直接使用维护中的上游桥接器输出契约。
- 发布流程加入桥接器运行时清单验证、安装包载荷校验、资产哈希、SBOM 和更新清单同步校验。
- GitHub Windows 构建工作流升级至 Node.js 24 兼容 action 版本，并完善 MSYS2 与 USB 运行时的 CI 发现和测试环境。

## 验证

- Windows x64 Release 应用、安装器和原生组件在 GitHub Actions 中构建。
- Native CTest、USB 桥接逻辑测试、应用逻辑测试与驱动安装器测试均在发布工作流中执行。
- Release 资产在发布前校验名称、大小、SHA-256、SBOM 和更新清单一致性。

This release improves wired and wireless mirroring, reverse control, keyboard input, orientation handling, and the release pipeline.

### Added

- Add maintained USB-bridge integration for wired and wireless reverse control, including keyboard text input and iOS hardware-button commands.
- Add configurable global shortcuts for individual control commands and mouse-button shortcut capture.
- Add first-connection device-profile guidance and clearer control prerequisite and failure dialogs.

### Changed

- Use the maintained bridge executable and runtime manifest directly across the application, installer, integrity validation, and release packaging.
- Persist wireless-mirroring settings and apply orientation-aware coordinate handling to wired and wireless control routes.
- Upgrade the GitHub Windows workflow to Node.js 24-compatible action versions and improve CI runtime discovery.

### Fixed

- Improve recovery from wireless landscape frame stalls without replacing the selected mirroring session.
- Restore keyboard input and system-button delivery for wired and wireless control routes.
- Release active drag state when the pointer leaves a mirrored preview and correct portrait/landscape input mapping.

### Notes

- Wired control requires an unlocked trusted device and Developer Mode when requested by iOS.
- Wireless control requires the device to be paired and reachable on the same local network.
