# iPhoneMirror v1.6.9

v1.6.9 是自 v1.6.8 以来的一次完整功能与稳定性更新。此版本重点完善爱奇艺等视频应用
投屏，加入媒体投屏的录制、直播推流、虚拟摄像头和独立预览能力，并同步升级窗口体验、
USB/Wi-Fi 接收、视频输出、更新安全和测试覆盖。

## 视频应用投屏与连续播放

- 修复爱奇艺投屏数秒后回到开头、重复播放开头、过早跳到节目结尾或自动切换下一集的问题。
- 参考常见媒体渲染器的 AVTransport 行为，支持上一集、下一集、当前媒体和待播放媒体信息；
  发送端请求下一集时不再返回会中断联播的动作错误。
- HLS 视频由内置 FFmpeg 统一处理播放列表刷新、分片拼接、加密密钥、时间戳不连续、临时网络
  失败、重连、跳转和真正的节目结束，WPF 播放器只接收连续的本地 MPEG-TS 流。
- 修复 Windows MediaElement 把单个短 HLS 分片误认成完整节目时长的问题，避免节目播到约五秒后
  被错误标记为结束或被发送端推进到下一集。
- 支持手机端和电脑端暂停、继续、音量、静音、十秒快退、十秒快进、精确点击跳转和键盘控制；
  对真正的直播流自动禁用不可用的进度跳转。
- 进度条统一使用节目时间轴而不是临时本地分片时间。拖动或点击后，滑块会锁定在目标位置，加载
  和重建 HLS 流时不再来回跳动；手机端进度控制也会同步生效。
- 新增倍速选择。媒体后端支持时会同步调整视频与媒体源音频速度；不支持的流会恢复为原速并提示。
- 增加明确的加载状态，在首帧出现或缓冲结束前保持可见，避免误以为播放已结束；移除预览区域
  重复的关闭按钮。
- 恢复 WPF 硬件优先合成，并让本地 HLS 桥接即时输出数据包，减少高分辨率视频画面的额外掉帧、
  成批到帧和不均匀播放。

## 媒体投屏预览、录制与直播

- 媒体投屏接入与设备镜像一致的顶部工具栏，可直接打开独立预览窗口、录制 MP4、进行
  RTMP/SRT/WHIP 直播推流和输出到 Windows 虚拟摄像头。
- 独立预览窗口使用 Windows 默认圆角；支持全屏、置顶、固定大小、旋转、静音、显示器选择和
  关闭等完整操作，且与主窗口预览互不冲突。
- 录制与推流直接从媒体投屏 URL/HLS 源解码其音频轨，不采集 Windows 扬声器回环、通知音、
  其他软件或麦克风声音。
- 暂停、继续、倍速、进度跳转和 HLS 重连时，媒体源音频会从相应节目时间重新同步；无音频轨的
  视频仍可正常录制和推流。
- 新增原生 NV12 视频帧导出，包含保持比例的黑边填充和 P010 到 NV12 转换。录制与推流直接使用
  NV12，减少高分辨率下重复的 BGRA 转换和内存复制。
- 视频、音频与 FFmpeg 管道泵全部移出 WPF UI 线程，避免编码压力冻结界面；限制长时间卡顿后的
  补帧数量并重新对齐墙钟时间，防止无限补帧造成延迟扩大。
- 自动探测并优先选择可用的 NVENC、AMF、QSV 或 Media Foundation H.264 编码器；不支持时保留
  libx264 软件回退。媒体投屏抓帧也避免逐帧强制完整 WPF 布局刷新。
- 虚拟摄像头帧通道仅允许当前用户和 Windows Frame Server 使用，防止其他进程读取或写入视频帧。

## 播放控件与界面体验

- 新增统一的媒体播放控制层：中央播放/暂停、音量、静音、时间显示、进度条、全屏、倍速与紧凑
  尺寸适配；控件在空闲时淡出，鼠标移入时恢复显示。
- 进度条恢复悬停时的轻微放大动画，并修复直接点击轨道、拖拽、鼠标捕获丢失和键盘跳转等交互的
  一致性。
- 录制与直播推流入口放置到画面调节按钮左侧，媒体投屏和 USB/AirPlay 设备镜像采用统一的输出入口。
- 统一主窗口、设置窗口、更新窗口、恢复提示和冲突窗口的标题栏、拖拽区域、关闭按钮、浅色/深色
  对比度与圆角策略；Windows/DWM 负责外层圆角，避免重复边框和圆角伪影。
- 改进独立预览窗口首次打开时的尺寸、居中和宽高比行为，覆盖横竖屏、旋转、混合 DPI、多显示器和
  高 DPI 情况，防止首帧闪现在屏幕原点或窗口尺寸跳动。
- 修复根页面过渡动画可能让新页面保持透明的问题；进入全屏时正确取消待执行的侧栏尺寸动画。
- 新增开发工具窗口的只读预览与运行信息检查入口，可查看界面、主题、语言、DPI、窗口数量、诊断、
  窗口状态和布局，不会执行真实网络、设备、更新或删除操作。
- 修复所有现有子窗口的关闭按钮与标题栏拖拽冲突，包括设置、更新、恢复、提示和实例冲突窗口。

## 设备接收与播放稳定性

- 改进 AirPlay 和 DLNA 的缓冲、直播流、待确认跳转、音量/静音和播放/停止边界处理，减少状态不同步。
- 媒体音量合并限制在当前播放命令边界内，避免上一个投屏会话的延迟音量命令影响新的媒体会话。
- 强化 Apple USB 父设备识别，按精确 VID/PID、拓扑和序列信息匹配，避免把接口节点或旧设备状态当作
  当前选中的 iPhone/iPad。
- 记录并恢复必要的 QuickTime/Apple USB 配置，只在确认需要时进行还原，减少启动、失败、取消和停止
  过程中的不必要重配置。
- 增加 Media Foundation 解码器、NV12/P010 帧复制和异常尺寸/步长/缓冲区的确定性校验，提升异常流
  与高分辨率输入的稳定性。

## 更新、安装与安全

- 更新安装助手通过无控制台方式启动，保留必要的 UAC 提权提示而不额外弹出 PowerShell 窗口。
- 便携版更新会在提权边界重新验证安装路径及其父目录的所有权和可写性，拒绝可能被替换的路径。
- 虚拟摄像头安装载荷会先复制到管理员限定目录，再启动提权安装程序，降低 DLL 侧加载风险。
- 驱动管理器在提权过程中锁定当前可执行文件，并拒绝不安全的替换路径。
- 主窗口、设置窗口和原生独立预览在关闭请求后会立即隐藏；录制、推流、虚拟摄像头、投屏与 USB 清理
  在后台受限时间内完成，避免桌面上残留窗口或退出过程无限等待。
- 安装版和便携版继续包含内置 FFmpeg、无线接收组件、虚拟摄像头、驱动管理器、SPDX 2.2 SBOM 与
  SHA-256 校验清单。

## 验证与兼容性

- 新增/扩展媒体命令顺序、HLS 连续播放、手机与电脑跳转、音量/静音、倍速回退、NV12/P010 输出、
  DLNA 控制、独立预览、窗口行为、更新边界、USB 配置与驱动提权路径的逻辑、运行时和原生测试。
- 正式版面向 Windows 10/11 x64，支持从 v1.6.8 覆盖升级。

### Added

- Add complete media-app casting controls, HLS playback bridging, independent
  preview, recording, RTMP/SRT/WHIP publishing, virtual camera output, direct
  source-audio decoding, speed selection, and native NV12 frame export.
- Add a read-only developer tools surface, safe previews for existing windows,
  and broader runtime, application-logic, native, driver, transport, and
  release validation coverage.

### Changed

- Standardize application and child-window chrome, themes, close behavior,
  DWM-owned corners, independent preview sizing, aspect handling, rotation,
  fullscreen behavior, and multi-display support.
- Use hardware-first WPF composition, immediate MPEG-TS bridge flushing,
  off-dispatcher media output pumps, direct NV12 output, bounded catch-up, and
  automatic hardware H.264 encoder selection for smoother playback and output.
- Strengthen AirPlay/DLNA playback boundaries, Apple USB identity/configuration
  handling, Media Foundation frame validation, and release/package consistency.

### Fixed

- Prevent iQIYI and similar HLS casts from restarting at the beginning,
  treating a short segment as a complete programme, ending prematurely, or
  advancing incorrectly to the next episode.
- Make desktop and mobile seeking deterministic while the visible programme
  timeline remains stable throughout buffering and local HLS stream replacement.
- Keep media-source audio synchronized across pause, resume, seeking, speed
  changes, and recovery without capturing unrelated system audio.
- Resolve window-close, title-bar drag, opacity-transition, preview sizing,
  update-helper console, virtual-camera channel, portable-update path, and
  elevated installer payload safety issues.
