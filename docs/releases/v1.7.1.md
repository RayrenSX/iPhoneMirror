# iPhoneMirror v1.7.1

v1.7.1 改进了 iOS 不允许采集的视频画面处理，并让采集失败更容易理解和恢复。

## 受保护视频与持续黑屏

- 有线采集会先等待正常视频帧，再判断后续出现的黑屏变化。
- 可能的受保护视频状态必须持续至少八秒，并采样到 24 帧近黑画面，同时检查亮度和中性色度。
- 不要求必须有音频：受保护播放可能继续发送 USB 音频，也可能完全没有音频；提示会报告实际观察到的音频状态。
- 提示使用谨慎措辞，因为长时间黑色场景、黑色页面、锁屏、解码失败和视频输出失败可能表现相似。
- 正常视频连续返回两帧后，程序会自动关闭提示并隐藏预览遮罩，不会断开当前会话。

## 紧凑采集提示

- 普通投屏失败使用简洁的红色错误提示，并提供直接重试操作。
- USB 配置失败使用带 USB 图标的独立琥珀色提示，并给出重新连接数据线的指引。
- 从控制中心停止的会话使用独立的琥珀色停止提示，并给出所需的设备重启指引。
- 采集恢复提示保留 Windows/DWM 原生外层圆角，不再在窗口周围绘制重复的亮色边框。

## 开发者工具

只读开发者工具目录现在包含以下预览：

- 普通投屏错误；
- 控制中心停止会话提示；
- USB 投屏配置错误；
- 受保护视频提示；
- 采集恢复指引；
- 现有的设置、输出、更新、启动、实例冲突和预览窗口。

所有预览均使用隔离的示例数据，不会执行设备、网络、驱动、更新或删除操作。

## 验证

- Windows x64 Release 原生 CTest：10/10 通过。
- 应用逻辑测试通过。
- WPF 运行时测试通过。
- 驱动安装器、Visual C++ 运行库、Apple 支持包和发布载荷校验通过。
- 便携版、安装程序、SPDX SBOM 和 SHA-256 资产清单均由发布脚本生成。

本版本不会绕过 Apple FairPlay，也不会让 iOS 拒绝提供的受保护画面变得可采集；
它只会在 iOS 提供持续黑色视频画面时给出清晰、可恢复的说明。

### Added

- Add sustained black-video detection for wired capture after a normal-frame warm-up.
- Add compact protected-video, capture-error, USB-configuration, and stopped-session notices.
- Add Developer Tools previews for the new notices and capture recovery guidance.

### Changed

- Require an eight-second, multi-frame near-black and neutral-chroma signal before showing the
  protected-video notice, reducing false positives from startup, short black scenes, and dark UI.
- Keep Windows/DWM outer corners for recovery and status notices while retaining compact internal
  status panels.
- Keep failed-session cleanup before ordinary error notices, and start stopped-session cleanup
  after the notice has been shown.

### Fixed

- Replace unexplained black video surfaces with cautious, recoverable guidance that does not claim
  DRM was definitively detected.
- Close protected-video notices and overlays automatically after normal video returns or a device
  switch.
- Remove duplicate custom borders that produced bright rings around native window corners.
