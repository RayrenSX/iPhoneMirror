## 2. USB iPad 原生 B 模式、方向与解码

- 为 iPad 原生 B 路径增加 Stevenote 与 H.264 4:4:4 能力协商，配套内置 FFmpeg H.264 High 4:4:4 软件解码路径。
- USB iPad 原生用途默认使用 4096×4096 的对称接收能力，修复横屏直接启动时可能降档的问题；高级自定义尺寸仍按用户设置处理。
- 增加只读系统方向辅助进程，经共存 USB mux 查询 SpringBoard 方向；无需为方向查询挂载 DDI、开启开发者服务或注入输入。
- 原生 B 根据系统方向旋转解码像素；普通 iPad B 根据视频样本中的方向附件转正。预览、截图与录制共用修正后的帧。
- 方向和接收时间随每帧 PTS 保存，处理解码延迟、输出乱序、方向历史淘汰及解码器重置，避免把新方向错误地套给旧帧。
- 原生输出缺少匹配的方向或时间戳元数据时不发布方向不确定的画面，转入兼容回退；明确的 0° 方向正常接受。
- 方向查询失败、方向过期或原生启动失败时回退普通 B；方向服务失效后撤销旧方向，但保留共享 broker，避免连带中断反控。
- 显示重配使用独立截止时间；即使音频持续到达且设备未发送显示释放确认，也能完成回退，不再一直阻挡视频。
- 原生静态画面在系统方向新鲜、音频健康时不再误触发视频停顿重连；音视频同时停滞仍执行恢复。
- 快速重连同时重置 FPS 采样计数、时刻和状态，修复帧计数清零后的无符号减法产生异常巨大 FPS。
- 完善硬件、DXVA 和软件解码候选链：运行中失败与替补首次输入失败均继续尝试剩余候选；全部失败后有限终止。
- 应用重启采集就绪等待改用单调时钟，最长 90 秒，覆盖 USB 激活、重枚举、握手、首帧和解码初始化；原生错误仍立即返回。

参考：[分辨率与旋转记录](../issues/54-resolution-fix.zh-CN.md)、[复审](../issues/54-review-20261017.zh-CN.md)。iPad15,7 / iPadOS 26.5.2 有原生 B 横竖屏与横屏启动实测；不能扩展为全部 iPad 或满 60 fps 承诺。

## 3. Cryptex / Personalized DDI 与无线准备回退

- iOS 27 的 Cryptex 准备遇到镜像拒绝、不兼容、无效镜像或服务不可用时，尝试原有 Personalized DDI 路径。
- 两条路径共用原准备总期限，保留首个错误诊断；已有镜像保留，不自动卸载或修改 nonce。
- 锁定、信任、身份不符、断连、网络、超时和验证失败继续报告对应错误；特别修复准备隧道超时被误归为可回退的服务不可用。
- 只有镜像实际复用或挂载验证成功后，才记住本会话的 Personalized 路线；后续 HID/RSD 重试复用该选择，避免再次走失败的 Cryptex 路径。
- 无线镜像服务不可用时，先检查实际控制隧道和 HID，避免镜像探测阻挡本来可用的无线控制。
- 无线确实缺少 HID 时，通过相同 UDID 的 USB 设备准备镜像，再重建无线会话；覆盖旧 iOS 与 Cryptex 路线，实际控制保持无线。
- 修复 Network → RemotePairing → USB 准备等嵌套回退反复初始化镜像的问题；成功状态在同会话共享，失败和取消不记录成功。
- 补齐镜像 inventory 查询阶段的设备错误分类，保留原始异常原因。
- 固定版本 Cryptex 下载即使 HTTP 200，但内容大小、哈希或格式无效，也会尝试同 revision 的 GitHub API 备用源；备用内容仍须完整校验。

## 4. USB / 无线反控就绪、认证与生命周期

- 桥接就绪必须同时满足认证门已打开、HID 存在及输入连接验证通过，修复条件判断遗漏。
- 应用只接受协议版本 2 的 ready 事件；携带 generation 时必须为正整数，同时兼容早期未携带 generation 的协议 2 桥接器。
- 媒体认证必须先收到实际数据才能报告控制就绪，首包等待最多 10 秒。
- 媒体接收失败、任务结束或连续 30 秒无数据时撤销认证与输入就绪；即使 HID PING 正常，也重建媒体认证和 HID，并保留采集 mux。
- 媒体认证模式同样支持有线 HID 定时刷新和就地恢复；持键或保持触点时推迟主动刷新。
- 替换 HID 的资源归原会话所有，退出时先释放替换连接，再关闭媒体认证门。
- 粘贴操作捕获输入代次，每一步按键及释放都与恢复过程同步校验；旧粘贴不能跨重连进入新 HID 会话。
- 增加采集 mux 端口租约，按设备发布本地回环地址，供方向辅助进程和反控共享；清理只移除该所有者发布的值。
- 借用其他进程 broker 的恢复分支不再重复接管 USB 接口；拥有者恢复后重新发布端口。
- USB 恢复失败后的桥接清理纳入停止操作，保持 Stopping 状态和资源所有权；采集拆除等待控制桥释放。
- 停止失败后允许再次停止，并发停止共享同一任务；清理未成功前不允许重新启动，切换传输前先释放旧桥。
- 存在恢复封锁设备时继续枚举其他设备；原生层跳过正在使用 USB 的设备，仅对其他设备探测新管理通道，避免一台设备阻塞多设备恢复。
- 修复 Wi-Fi 同步助手未启动或清理异常时的锁泄漏，两把锁分别保证释放。

参考：[控制全流程审查](../CONTROL_FLOW_AUDIT_2026-10-17.zh-CN.md)、[重试与回退修复](../LOGIC_RETRY_FALLBACK_FIXES_2026-10-28.zh-CN.md)。

## 5. 蓝牙 F9、输入隔离与独立窗口

- 已建立并校准的蓝牙连接，F9 改为暂停/恢复输入，保留 GATT、目标设备和校准状态；正常恢复不再重复连接、校准或弹出提示。
- 暂停立即释放本机光标限制和鼠标捕获，再异步释放手机端按键；快速连续切换串行执行，恢复等待上一轮释放结束。
- 首次连接倒计时仍有效；迟到倒计时不能解除用户暂停。未校准、断连或传输失败时不允许直接恢复。
- 暂停所需的鼠标及已使用键盘、consumer、navigation 释放报告必须实际成功；失败或超时则关闭连接，避免手机残留按下状态。
- 输入生产者、发送队列、重试及快捷键迟到释放均校验输入会话与暂停代次；旧鼠标、按键和松键不能进入恢复后的新会话。
- 失焦时丢弃旧移动和滚轮，允许同一有效会话发送空释放报告；恢复前激活并复查对应窗口，防止意外捕获其他窗口的桌面输入。
- 选择另一设备后按 F9，先停止旧目标，再启动新目标，避免恢复到旧设备。
- WinRT 通知必须同时满足成功状态、完整发送字节数及无协议错误；失败按传输故障处理。
- 独立窗口只在输入开启期间临时按客户区处理，暂停后恢复画面拖动；保留用户手动固定窗口的设置，并释放对应独立 HWND 的鼠标捕获。
- 显式停止、关闭窗口和切换传输仍执行完整蓝牙关闭；暂停期间从菜单启动可恢复输入。

## 8. 原画虚拟摄像头与媒体输出

- 优化 SDR NV12/P010 → BGRA 批量转换，原尺寸输出走连续行转换；既有 HDR / 广色域处理保留。
- 60 fps 虚拟摄像头先检查轻量源时间戳，新帧到达后再取像素；定期完整读取，兼顾静态画面、相同时间戳像素更新及源丢失检测。
- 没有独立源时钟的媒体投屏按选择的帧率取帧，避免高频全帧转换。
- 连续 USB 解码使用双缓冲 GPU 回读，保留原帧时间戳、颜色与顺序；drain 输出尾帧，flush 丢弃旧缓存。
- 摄像头增加独立接收线程及最多 5 帧的有界队列，启动最多预缓冲 3 帧，慢消费者丢弃最旧帧；批量行拷贝和线程调度减少输出开销。
- 原画虚拟摄像头按源尺寸建议输出，支持竖屏尺寸、16 像素宽度对齐、偶数高度及总像素上限。
- 录制、直播和虚拟摄像头的启动按钮在运行时原位切换为停止；各输出独立停止，当前参数即使被改为无效值也能停止。
- 录制保存/丢弃动作集中在录制页，改善并行输出状态更新与可用性。
- 录制已编码完成但文件发布/改名失败时保留 MP4 和完成标记，支持保存重试及应用重启后发现成品。
- 新录制不得覆盖仍未保存的已完成文件；区分完整成品与中断的临时文件，保存失败明确提示文件仍可保存。

参考：[虚拟摄像头修复与实测](../VIRTUAL_CAMERA_60FPS_FIX_2026-10-29.zh-CN.md)。该机器 Windows 摄像头直接读取约 59.84 次不同画面/秒，OBS 开启缓冲后全段约 58.13 次/秒；有界队列和双缓冲会增加数帧延迟。

## 9. 无线接收、DLNA 与 HLS

- Original 和 UxPlay 共用启动失败保护，避免后台轮询不断重启失败宿主；启动调用失败后退避 30 秒，手动应用可重试，确认 Ready 前保留错误。
- DLNA 失败通过 IPC 明确报告降级状态，不再伪装完全就绪；每 5 秒独立重试，恢复后清除降级，AirPlay 及其 URL 播放命令继续可用。
- HLS 只有桥接进程退出码为 0 才算节目完成；异常退出进入恢复退避，已释放进程不视作成功，恢复保留播放进度。

## 10. 应用内更新与安装

- 修复 x64 PowerShell 将 x86 Inno Setup 暂存于 System32 时受 WOW64 重定向影响而无法启动的问题；提权暂存改用 Program Files 下受保护的随机目录。

- ZIP 准备最多等待两分钟，取消/超时通知助手停止；扫描、解压和等待进程期间均检查取消，避免旧助手继续替换文件。
