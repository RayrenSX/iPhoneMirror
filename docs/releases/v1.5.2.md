# iPhoneMirror v1.5.2

v1.5.2 是更新功能的紧急修复版本。它解决了应用已经成功连接 GitHub、找到新版本，却在打开“发现新版本”窗口时显示以下错误的问题：

```text
无法检查更新：设置属性“System.Windows.UIElement.RenderTransform”时引发了异常。
```

## 受影响版本与升级方式

该问题已在 v1.5.0 到 v1.5.1 的实际日志中确认。由于错误发生在旧版本自己的更新窗口中，旧客户端无法通过“一键更新”按钮完成这一次修复。

请从本 Release 手动下载并运行 `iPhoneMirror-Setup-v1.5.2-x64.exe`。安装器会覆盖升级现有版本，不会重置 `%LOCALAPPDATA%\iPhoneMirror` 中的主题、语言、更新选项或设备设置。安装 v1.5.2 后，后续应用内检查、下载和启动安装器流程恢复正常。

## 根因

GitHub Release 请求和版本解析均已成功，故障不在网络连接。更新窗口的 XAML 将 `RenderTransform` 直接设置在顶层 WPF `Window` / `FluentWindow` 上。WPF 在运行时解析编译后的 BAML 时会调用 `Window.CoerceRenderTransform`，并抛出“转换对于 Window 无效”。

这个问题没有在普通构建中被发现，因为 XAML 编译器允许生成对应 BAML，异常只会在真正调用 `UpdateWindow.InitializeComponent()` 创建窗口时出现。

移除该变换后，运行时测试又发现同一窗口的进度条使用默认双向绑定连接到只有私有 setter 的 `ProgressValue`，这会成为下一个窗口加载错误。v1.5.2 同时修复了两处问题。

## 修复内容

- 移除顶层 `FluentWindow.RenderTransform` 和窗口级手写淡入动画。
- 将现有共享 `PageTransition` 应用到内部根 Grid，在合法的内容元素上保留相同的淡入和轻微位移动效。
- 将下载进度 `ProgressBar.Value` 显式设置为 `Mode=OneWay`，避免 WPF 尝试回写只读公共属性。
- 保留自动下载、手动下载、取消、重试、SHA-256 校验和安装器启动逻辑，不改变更新协议或资产选择规则。
- 在补充原生依赖信息并重写 SPDX 清单后重新生成其内嵌 SHA-256 边车文件，确保便携包中的 SBOM 校验值与清单内容一致。

## 回归保护

本版本新增独立的应用运行时测试项目，并接入标准 `build.ps1` 与 GitHub Actions 流程：

- 在 STA 线程中创建真实 `App` 并加载 `App.xaml` 资源。
- 从本地 JSON fixture 解析一个模拟的新版本，不访问网络。
- 构造真实 `GitHubReleaseClient` 和编译后的 `UpdateWindow`。
- 调用 `InitializeComponent()` 完整解析 BAML、资源、模板和绑定后关闭窗口。
- 任意窗口级非法变换、只读属性双向绑定或缺失资源都会让构建失败。

静态 UI 测试也新增了通用规则，禁止应用及驱动管理器的子窗口直接设置 `RenderTransform`，并锁定更新进度必须使用单向绑定。
