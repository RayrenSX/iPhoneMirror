# 设备管理与脚本接入

本文以本地 v1.8.5-pre7 为基准，说明设备管理的权限、文件映射和开发接入。日常操作见[使用指南](USER_GUIDE.md#管理应用与文件)。本版变化见[pre7 发布说明](releases/v1.8.5-pre7.md)。

入口为主窗口左侧的「设备管理」图标。面板在投屏右侧展开，跟随当前选中的设备，只显示「应用」和「文件」。设备信息、连接能力、描述文件、日志、手机控制与 IPA 安装位于「开发者工具 → 设备工具」。两个入口均跟随左侧当前选中的设备并复用已建立的连接。开发者窗口切回常规工具或关闭后会停止该页的后台任务。

应用、进程、描述文件和文件均可点击行内「…」或右键操作；菜单会选中指向的条目，空白处只显示页面操作。应用和文件支持双击及 Enter；F5 刷新当前页，保留列表选择和滚动位置。IPA 和描述文件安装放在开发者设备工具的标题栏「更多」菜单，主窗口应用菜单不再提供 IPA 安装，底部只显示数量或简短状态。

应用菜单中的「关闭应用」会向所选 iPhone 上该应用的主进程发送终止信号。请求被设备接受时，底部会提示「已请求关闭」。未找到运行中的主进程时，会提示「未在运行」。

搜索支持一键清除、Esc 清空及 Ctrl+F 聚焦，进程也可按名称、路径或 PID 搜索。搜索无结果时可直接重置条件；空描述文件、空目录和未开始的日志均有对应引导。文件页以「加载更多」追加内容，刷新保留已加载页；返回上级会选中刚离开的目录，支持 Backspace / Alt+↑，点击地址栏编辑路径、Esc 取消编辑。读取目录失败会保留原地址和内容。日志的开始 / 停止按钮按当前状态切换，停止后仍可筛选和保存。

应用按 A–Z 首字母分组，中文按拼音首字母归组，数字与其他字符归入「#」。列表保持虚拟化；图标在列表显示后按可见范围加载，缩略图保存在 `%LOCALAPPDATA%/iPhoneMirror/AppIcons`，按设备、Bundle ID 和版本隔离。刷新和重启可复用缓存，版本更新会重新读取；磁盘不可写或缓存损坏时仍可正常显示列表并从手机补取图标。

应用右键和行内「…」菜单提供「以 Metal 性能 HUD 重启」。确认后只关闭并重新启动所选设备上的所选 App，使用 `MTL_HUD_ENABLED=1` 请求 Apple Metal 性能浮层；未保存内容可能丢失。普通「打开」、双击和 Enter 仍只打开应用，不重启旧进程。HUD 通常显示 App 侧 FPS、帧间隔、GPU 时间和内存等，具体取决于系统和应用；成功状态只表示启动请求完成，需要在手机或投屏画面确认浮层。结束目标 App 后从手机图标普通启动可恢复不带 HUD 的进程。

此功能复用设备管理的开发者模式、匹配 DDI 和现有设备隧道，无需在手机安装额外 App。只对支持 Metal HUD 的目标 App 生效，不是系统全局监控；部分应用可能拒绝开发者启动。App 侧 FPS 与底部投屏接收帧率含义不同。基础功能不收集历史性能曲线或导出报表。该动作也可经现有鉴权 Hub 接口以 `restart_with_metal_hud` 调用，仅接受 `bundleId`，需要当前控制租约。

文件页的「导入文件…」可多选电脑上的文件，上传到当前已打开的媒体目录；尚未提交的地址编辑不会改变上传位置。同名文件自动以「文件名 (1).扩展名」等名称保留副本。完成后自动刷新；中途失败会保留已完成的文件并报告数量，未完成的文件会清理。崩溃报告目录只支持读取和导出。导入到媒体目录不会自动添加到 iOS「照片」图库。

普通媒体文件的右键和行内「…」菜单提供「删除文件」，确认框显示名称和完整路径。确认后只删除所选文件并刷新当前目录，不递归删除文件夹；若文件的大小或修改时间已变化，会要求刷新后重新选择。取消确认、切换设备或切换页面后，旧菜单和确认结果不会触发删除。删除为界面私有操作，不通过通用 HTTP Hub API 暴露。

## 已保留的功能

| 页面或入口 | 功能 |
|---|---|
| 开发者工具：信息 | 设备、系统、电池、存储、可用能力和隧道信息；只读信息可选中复制 |
| 应用 | 名称 / Bundle ID 搜索；用户、系统、开发、轻 App 筛选；真实图标；打开、卸载；切换进程列表后可结束进程；安装 IPA 位于开发者设备工具 |
| 开发者工具：描述文件 | Provisioning / 配置描述文件列表、安装、移除；配置安装仍需手机确认 |
| 文件 | 媒体文件、应用共享文档、崩溃报告；目录浏览、分页、文件导入、确认后删除文件、分块另存为、报告导出；媒体和共享文档可映射到资源管理器 |
| 开发者工具：日志 | 开始、停止、筛选、跟随和保存实时日志 |
| 开发者工具：控制 | 主屏幕、应用切换器、锁屏、音量；读取和应用手机设置；模拟定位 / 恢复；确认后重启或关机 |
| Python SDK / MCP | 鉴权 HTTP API、设备选择、控制租约、截图、输入和设备管理；36 个 MCP 工具 |

不支持的手机设置项在读取后直接移除显示。应用安装需要有效签名及设备许可，不能绕过 iOS 安装限制。定位、安装、删除和电源操作不会自动重试。

## CoreDevice 投屏（实验）

在主窗口「投屏来源」选择显示为「已配对 · 无线在线」的 iPhone 或 iPad，点击「开始投屏」即使用 CoreDevice；设备右键菜单不再提供单独的 CoreDevice 投屏入口。画面显示在主预览区，通过「停止投屏」结束。开始前先停止同一设备的其他投屏。设备需要 iOS 或 iPadOS 27 及以上、开发者模式和已挂载的开发者镜像。若设备提示媒体被占用，退出相机、录音或通话后重试。

2026-11-24 在 iPhone 17 和 iPad A16（27.2.1）上收到原生 HEVC 视频并在 Windows 解码。iPhone 12 mini（18.7.8）报告媒体能力为 0，启动请求返回 9021，继续使用常规 USB 或 AirPlay 投屏。当前实验入口只传画面。媒体启动和停止由桌面应用通过专用本地桥通道处理。

预览跟随设备界面方向。已知型号使用屏幕原生像素尺寸，再由 Windows 预览按窗口大小显示。当编码画布接近物理面板尺寸时，各档位沿用原生档位的相同显示范围。无有效尺寸且无法按画布与面板的比例处理时，可根据中性灰留边估算显示区域。解码器并行处理同一帧内的分片和参考图像缩放，按顺序完成各帧。底部帧率统计实际进入预览的帧。诊断日志分别记录设备送达、解码、管道输出和 D3D 显示帧率。快速滑动时帧率仍可能受设备编码速度影响。[rPlayHub 的 RVRA 说明](https://github.com/rPlayAI/rPlayHub/blob/main/doc/RVRA-AND-PORTABILITY.md) · [ZenLink 的解码与显示说明](https://github.com/zenvyzenshiro/zenlink)

实时 CoreDevice 投屏由解码器将像素直接写入主窗口的专用管道，桥接器只传入编码数据并接收出帧确认。预览读帧变慢时，解码器继续处理编码数据，预览最多保留两张待显示画面。

停止 CoreDevice 投屏会结束手机端媒体服务和远程观察。若投屏与反控共用媒体流，该设备的反控同时关闭。桥接器核对系统报告的会话归属，仅在服务空闲或所有会话属于当前桥接时发送停止请求。查询、停止及确认分别使用独立连接，避免手机的媒体服务在同一连接发送第二个回执时中断。

编码档位切换时，解码器按每帧尾部的有效尺寸重采样参考帧。桥接器处理 HEVC 尾部不同长度的转义字节，包括 iPhone 17 在滑动时使用的 720×1280 档位。同一编码画布的连续预测帧若没有尺寸，可沿用上次的有效尺寸。实时收包为乱序片段保留一个短窗口。实际丢包或确认画面损坏时会请求关键帧，编码连续切档时等档位稳定再刷新，静止期间每次停发只探测一次。诊断日志会记录编码档位、关键帧请求、乱序恢复、RTP 序号缺口和最长送帧间隔。

内部编码流重放和 RTP/RTCP 测试继续用于验证解码与 HID 会话保活。

## 连接与恢复

文件页的目录下拉框会列出支持文档共享的 App，显示为「App 名称 · 应用文档」。选中后访问该 App 开放的 Documents 目录，可直接导入、另存为和删除文件。

开启「映射到资源管理器」会建立一个统一的「映射文件夹」根目录，包含媒体文件、崩溃日志及实测可访问的应用目录。扫描所有已安装应用，优先使用能正常打开的完整应用数据目录（含 Documents、Library、tmp 等），否则尝试共享 Documents，再尝试 CoreDevice 应用数据域；还探测临时文件、系统崩溃日志及安装信息提供的应用共享组。只加入能成功读取目录的项；扫描分页显示进度，关闭开关可取消。切换页面内的目录不会撤销映射。

媒体与 House Arrest 应用目录保留设备允许的读写能力，崩溃日志及 CoreDevice 文件服务域只读。设备返回的文件权限、不可变标记或明确只读标记会传到 Windows 的只读属性与 WebDAV 权限，禁止写入、改名、删除和元数据修改；只读子项会在递归删除预检时阻止删除。AFC 未提供权限信息时不通过试写探测，实际写入被手机拒绝后，该路径在本次映射中标为只读。Windows 属性设置不能解除手机端只读限制。跨服务或跨应用移动会拒绝，可使用复制。

映射还包括实测可打开的「系统目录（可浏览部分）」和「系统共享库」。前者只显示可浏览的目录，后者列出设备开放的共享库文件并按需读取内容，均为只读。Windows 不支持的手机文件名会转换成可用名称显示，原始手机名称不变；可读取且不离开当前服务根的链接只读展示。少数条目无权限或失效不会隐藏其他同级项。

映射先验证媒体和崩溃日志服务并挂载盘符，再后台逐项发现其他可访问目录，发现后通知资源管理器刷新。后台优先探测声明文件共享的应用，但仍遍历其余应用和应用组；打开文件或浏览目录会暂停后台探测，让文件操作先执行，随后从被打断的页继续。目录显示名缺失时使用应用或服务标识，不会因一个可选字段缺失而让整个映射失败。

映射根目录和资源管理器盘符默认显示当前设备名称。目录树每次成功读取后保存到 `%LOCALAPPDATA%/iPhoneMirror/ExplorerTreeCache`；同一设备、型号及系统版本再次映射时，先显示上次的根目录与已浏览文件夹，再后台校验并刷新。缓存保留文件权限和精确修改时间，不保存文件内容或连接凭据；读取内容、删除和覆盖前仍取得实时快照，写入或冲突后使相关缓存失效。缓存损坏时回退到手机读取。已浏览目录最多缓存 1024 个、合计 50000 个条目和 16 MiB，保留七天；后台完整扫描后移除已不可用的应用入口。

各应用使用手机允许的 House Arrest 或 CoreDevice 范围，不包含未经手机授权的数据或 iCloud 云盘。映射默认关闭，设备/控制断线或程序退出时清理，Windows WebClient 的传输限制沿用现有系统设置。

打开设备管理、切换设备或重新打开面板时，只会复用当前设备已有的可用通道。需要新建连接时，点击「启用反控并连接」，也可先通过投屏工具栏开启反控。连接列表中断时可从面板右上角的三点菜单重新连接。首次连接仍需要解锁、信任电脑，以及必要的设备绑定、开发者模式和匹配 DDI。连接期间显示静态状态，失败后可点「重试连接」。切换设备或隐藏面板会取消由面板发起的连接；若加入其他入口正在建立的连接，则只取消面板的等待。

开始或停止 USB 投屏可能触发管理通道重连。面板保留当前列表、筛选和选择，暂停设备操作；通道恢复后自动刷新当前页，无需切换设备。就绪判断来自管理桥，独立于普通 USB 枚举状态。面板显示期间每 500 毫秒只检查内存连接状态，不主动扫描或新建连接；需要新连接时仍由用户点击连接入口。切换设备、切页或隐藏面板会取消旧任务，旧响应和旧菜单不能影响新设备。

刷新、加载、断线状态均使用同一套主题模板，不再使用会变白的系统 ListBox 禁用模板。既有「应用、投屏、反控」三类常规设置保持原有组织。

## 脚本与构建

```powershell
python -m pip install -e './sdk/python[mcp]'
# 使用说明与鉴权配置见 sdk/python/README.md
./scripts/build_dev.ps1 -MsysRoot C:/msys64
```

需要 .NET 10、Visual Studio C++ 工具链、CMake、Python 3.13；重建解码器还需 MSYS2 UCRT64 gcc、make、patch、nasm。脚本构建现有桥、离线解码器、原生 Core 和应用。交付从整合后的 main 构建到 `outputs/iPhoneMirror-main`，不覆盖正在运行的目录。

```powershell
python -m unittest discover -s tests -p device_hub_test.py
python -m unittest discover -s tests -p device_management_test.py
python -m unittest discover -s tests -p device_file_import_test.py
python -m unittest discover -s tests -p device_file_delete_test.py
python -m unittest discover -s tests -p python_sdk_test.py
python -m unittest discover -s tests -p coredevice_media_test.py
# 构建 Runtime.Tests 后运行：
$runtime = './src/App.Runtime.Tests/bin/Release/net10.0-windows10.0.19041.0/win-x64/IPhoneMirror.App.Runtime.Tests.exe'
& $runtime --device-hub-sidebar 'outputs/diagnostics/device-hub/sidebar'
& $runtime --device-hub-file-import 'outputs/diagnostics/device-hub/import'
& $runtime --device-hub-file-delete 'outputs/diagnostics/device-hub/delete'
& $runtime --device-hub-auto-connect 'outputs/diagnostics/device-hub/connect'
& $runtime --device-hub-placement 'outputs/diagnostics/device-hub/placement'
& $runtime --automation-api
```

内部 `--coredevice-replay` 回归需要自备合法、脱敏的 `.imrtp` 样本，不是普通用户的媒体回放入口，标准交付不附真实手机录制样本。

读取、日志、文件和安装操作的能力不能互相作为成功证明；安装、卸载、描述文件、电源和定位等操作需在明确目标设备上分别验收。上面的离线与替代委托测试不等于这些操作已在所有手机通过。解码器许可证和来源见 [third_party/rplayhub](../third_party/rplayhub/README.md)。
