# 键盘映射

## 使用

在「投屏设置」的「反向控制设置」下方打开「键盘映射 → 管理键盘映射」。默认关闭，默认没有任何绑定。

1. 选择当前 iPhone/iPad，开启现有 USB 或无线触控反控，等待设备画面与反控就绪。
2. 点击「添加映射」，向导自动等待录入一个物理按键。松开按键后点击「下一步」。重复按键和快捷键冲突在当前步骤内提示。
3. 选择点击、长按、按住直到松开、双击或滑动。长按设置时长，双击设置间隔，滑动选择方向；点击与按住操作自动跳过参数页。
4. 点击「选择位置」或「开始录制手势」，在原来的投屏预览框中取点；滑动则按下、拖动、松开，自动记录起点、终点和时长。完成后返回向导显示摘要，可重新取点。取点期间向导和管理窗口暂时隐藏，不遮挡原画面。
5. 在确认页检查并点击「完成」，短暂显示保存成功后回到列表。启用键盘映射，点击投屏画面使其获得焦点，再按绑定键。主预览和当前设备的独立预览持续显示按键标记。

向导底部始终显示取消、上一步和下一步/完成。返回保留草稿，已完成步骤可以点击返回；编辑已有映射会预载按键、参数和位置。取消未修改的编辑直接关闭，有修改则先确认放弃。详细架构与验证边界见 [KEYBOARD_MAPPING_WIZARD.md](KEYBOARD_MAPPING_WIZARD.md)。

录入结束后，Enter 进入下一步，Esc 取消，Alt+左/右切换步骤。录入事务本身优先接收物理按键，因此录入期间 Enter / Esc 仍可作为映射键；点击按键预览可停止或重新开始录入。编辑器打开期间暂停映射和设备直发键盘输入，关闭后恢复原有路由规则。

「按住直到松开」在键盘按下时按住所选目标点，直到该物理按键松开才释放，无需设置持续时间；原有「长按」仍按固定时长执行。快速松键不会留下延迟触点，多个按住映射可独立释放。

## 自定义游戏控制（开发分支）

管理窗口可新建、复制、重命名、删除、导入和导出方案。每个方案有独立映射列表；旧版单列表配置会迁移为一个方案。向导可选择键盘、鼠标按键或滚轮方向作为输入，并提供以下动作：

- **方向控制**：依次录入上、下、左、右四个物理键，选择摇杆中心和半径；同时按两个方向键时保持圆形范围，可设置起步和转向过渡。
- **相对鼠标拖拽**：选择触发键和起点，设置水平/垂直灵敏度、半径、反向、按住或切换模式。激活期间使用原始鼠标位移；到达边界时可抬起触点并从中心继续。
- **循环目标点**：每次触发依次点击所选位置；**释放指针**可手动结束持续控制。普通定时动作也可设置完成后释放指针。

持续控制使用当前 USB/无线触控会话，复用五点触控额度；失焦、停用映射、切换设备或断线时结束触点并恢复鼠标指针。USB 持续控制要求桥接器支持触控 ACK；仅构建应用不会重新打包桥接器。旧桥接器会拒绝启动持续动作并在界面提示更新。当前自动化验证了配置迁移、连续控制生命周期、触控 ACK 顺序和窗口布局；瓦手实际对局手感仍需真机验收。

2026-10-05 开发分支验证：Release 构建及独立程序发布通过，零警告、零错误；自定义控制、完整键盘映射、原生取点、映射向导、统一键盘路由及本地化审计通过；139 个 USB Python 测试通过。连续控制范围在三种设备尺寸、四种旋转、方向及反转组合下保持一致。新桥接器离线运行时检查通过，发布目录的 835 个运行时文件与校验清单一致。

列表更改自动保存；编辑窗口需在确认页点击「完成」。每条映射可独立开关、编辑、删除。重复按键可以重新录入、明确替换或编辑原映射。保存失败保留草稿和错误提示，不丢失已有设置。

取点先去除视频黑边，再复用鼠标反控的方向转换，保存归一化设备坐标。标记随窗口缩放和方向重新投影；旧配置仍按原有画面坐标解释。滑动方向表示手指移动方向，拖动记录起点、终点和持续时间。起点、终点必须在画面内，不能相同。持续时间为 50–10000 ms，双击间隔为 40–1000 ms。

普通显示状态下标记穿透鼠标，不阻止操作其下方的手机内容；仅取点时接收鼠标。保存、删除、单条禁用和重新启用立即更新标记。关闭映射或设备画面失效会隐藏标记；切换设备、会话或方向时取消未完成的取点。

## 按键与暂停规则

- 按扫描码和扩展标记绑定物理位置；键盘布局切换不会改变绑定位置。数字、小键盘、方向键、导航键、空格、回车、Tab、Esc、功能键等均可录入。
- 普通按键按下一次执行一次，系统自动连发不重复执行。同一设备最多五个不同映射同时执行；同一映射未结束时不重复启动，超出上限不积累动作队列。映射与鼠标、触摸屏共享五点额度。
- Ctrl/Shift/Alt 的定时动作在单独松开时触发，参与组合键则不触发。「按住直到松开」在单独按下时开始，松开或按下其他键组成组合键时释放。修饰键不被映射功能拦截。
- 左/右 Win 可以分别录入。绑定的 Win 单独松开时执行定时映射并阻止开始菜单；「按住直到松开」则在按下时开始，松开或组成组合键时释放；参与组合键时取消单键映射并重放被暂存的 Win 按下事件，让 Windows 处理组合键。系统快捷键的实机验收见修复记录。F5/F11 保留给现有刷新/全屏，其他现有单键快捷键也检测冲突。Esc 在全屏时保留退出行为。
- 可选「阻止已映射普通按键的原始 Windows 行为」。默认不阻止；没有可用映射目标时也不拦截。
- 编辑映射、取点、操作设置/子窗口、文本输入、隐藏到老板键模式或无法可靠确认焦点时暂停。返回实际原生投屏窗口后恢复，不要求关闭后台管理窗口。外部应用的文本/文档控件采取保守暂停策略；不是所有第三方 UI 都能提供可识别的非编辑焦点。
- 设备断开、切换、重新连接、画面尺寸/方向变化或焦点变化会取消在途动作；清理释放只发送到原控制会话，不发送给新设备/新会话。
- 软件注入的键盘输入不触发映射。

## 后端边界

USB 和无线模式复用现有绝对触控通道。现有蓝牙 HID 仅提供相对鼠标，无法可靠定位指定百分比坐标，因此蓝牙模式不执行这些映射，界面会说明并提示切换 USB/无线。原有蓝牙键盘、鼠标和快捷键保持可用；不会创建另一套连接、协议或校准系统。

## 架构

输入路径：现有 `MainWindow` 全局键盘 hook → `KeyboardMappingKeyState` → 有界 `KeyboardMappingExecutor` → 当前 `DeviceControlSession` / `ReverseControlInputRouter` → 现有 `UsbTouchBridgeHost`。

- 共用已有 `WH_KEYBOARD_LL`，映射关闭后不保留映射监听；录入或原有反控仍需要时，由共用生命周期保留 hook。
- hook 内不查询 UI Automation、不做磁盘或设备 I/O。外部焦点由后台单工作项缓存，原生焦点事件使缓存失效；未知/过期结果拒绝执行。
- 目标复用 `SelectedDevice` 与现有身份绑定，不另建设备管理器。发送前和写锁内校验选中设备、路由代次及桥接代次。
- 每个映射手势和触摸屏接触分配独立触点 ID；原有鼠标触点 ID 1，避免相互释放。USB/无线共用五点上限，桥接报告始终包含全部仍按下的触点，见[五点触控](FIVE_POINT_TOUCH.md)。
- 鼠标点击和取点共用 `PreviewCoordinateMapper` 的视频内容矩形，以及现有 `BluetoothMouseOrientationMapper` 的方向/反转设置。`MappingPreviewSurface` 组合这两个转换，并用于标记的反向投影。
- `KeyboardMappingCapture` 在 KeyUp 确认录入；显式取消或关闭窗口时，事务代次使排队回调失效。`KeyboardMappingWindowsKey` 单独处理 Win 的延迟执行与组合键重放。
- `KeyboardMappingOverlayWindow` 使用原生预览所属窗口的透明 owned HWND 跨越 D3D airspace，普通模式无激活且鼠标穿透，取点模式临时接收鼠标。
- 配置位于现有 `UpdateSettings.KeyboardMapping` / `settings.json`，含版本、总开关、原始键行为选项和映射列表。损坏条目被隔离，映射关闭等待用户检查，不重置其他设置。
- 复用 RoundedWindow、Card、Button、AppPrompt、主题和本地化资源。诊断包含配置、冲突、匹配、目标、执行/取消/失败；高频动作日志按类别限速。

UI 和键盘测试应串行运行，避免相互抢焦点。截图和本地验证配置在被 Git 忽略的 `artifacts/keyboard-mapping/` 下。生产设置不会新增默认绑定。

交付测试版时必须同时更新触控桥接器：单独 `dotnet build` 只复制 `dist` 中已有的桥接二进制，不会编译 Python 源码。旧桥接器会导致按下第二个映射键后第一个触点消失。应先使用 `scripts/UsbBridgeBuildSource.ps1` 和桥接构建配方打包当前 `tools` 源码，再构建应用；对最终目录中的 `tools/iUsbBridge.exe --check-runtime` 进行检查，确认 `functional_checks` 含 `simultaneous_contacts_independent_release`。该检查离线验证多触点报告与独立释放，不操作手机。

真机动作测试必须人工确认设备已解锁、信任电脑、开启开发者模式，且当前页面可安全点击/滑动。测试坐标针对当次观察页面，不是生产默认值。不要在任意手机页面直接运行 `--keyboard-mapping-live-actions`；先审查 `KeyboardMappingLiveTest.cs` 中的动作坐标。
