# 有线投屏清理后的自动 USB 重连

2026-10-09：已实现并在 iOS 26.6.2、iOS 18.7.8 真机验证。本项处理关闭投屏后普通 USB 配置已恢复、Apple 管理服务仍漏列手机的故障；完整有线/无线及所有用户环境的原任务仍未完成。

## 行为

停止控制并释放投屏资源后，先执行既有配置恢复。恢复观察到期后，如果独立 hub 查询确认配置为 3、指定手机父节点和管理接口均启动、Apple USBMux 仍没有该设备，才尝试一次该手机所在端口的 `IOCTL_USB_HUB_CYCLE_PORT`。普通恢复成功时不触发端口重连；照片接口缺失不阻止故障恢复。

助手根据指定 UDID 找到唯一 Apple 手机父节点，重新读取当前端口的实际序列号，核对 VID/PID、配置、父节点、hub 和端口，再提交一次原子端口重连。拒绝缺失、歧义、序列号读取失败、另一台手机、hub、过期请求和仍在投屏的配置。没有独立 disable/enable 两步，避免程序中途退出把设备留在禁用状态。

Windows 要求管理员权限。普通权限下请求系统 UAC 授权；取消或无法授权时保持失败结果和重新插拔指导。清理状态补齐四种语言的授权说明。普通关窗时间预算包含授权和恢复观察。授权请求带单调时间期限，迟到的授权不会再执行端口重连；该期限约束操作提交，Windows 授权界面本身由系统管理。

端口请求成功仍不等于恢复成功。原生继续等待指定 USBMux 行与正常 PnP 栈稳定出现，失败保留停止警告和再次启动保护。验收另外要求真正启动有线控制、取得手机 HID 应答，不能只看助手退出 0。

## 真机证据

证据位于 `work/two-device-review/`，整个恢复测试没有物理拔插、服务重启、驱动更换或配对文件改写。初始普通权限请求被 Windows 拒绝，原始失败记录保留。管理员单端口重连恢复了两台此前已点信任但 Apple 服务漏列的手机。

| 测试 | 结果 | 证据前缀 |
| --- | --- | --- |
| iOS 26 只投屏后关窗 | 28.10 秒；自动重连成功；随后两次有线控制启动和 6 次真实 HID 应答 | `usb-reconnect-ios26-window-2`、`usb-reconnect-ios26-native-window-2` |
| iOS 26 投屏与控制后关窗 | 28.16 秒；自动重连成功；随后两次启动和 6 次应答 | `usb-reconnect-ios26-window-3`、`usb-reconnect-ios26-native-window-3` |
| iOS 18 投屏与控制后关窗 | 13.49 秒；普通恢复成功，未额外重连；随后两次启动和 6 次应答 | `usb-reconnect-ios18-window-1`、`usb-reconnect-ios18-native-window-1` |
| 双设备隔离 | iOS 26 关窗 28.22 秒、自动重连并取得 6 次后续应答；iOS 18 同时持续 65.82 秒、64 次应答、输入代次始终 1 | `usb-reconnect-ios26-window-isolation`、`usb-reconnect-ios18-during-peer-cleanup` |

`window-2` 的测试入口曾误进入只投屏分支，实际日志明确记录 reverse control never started，按只投屏验收；后续 `window-3` 和 isolation 已修正并确实启动投屏共存控制。首轮 `window-1` 的恢复条件过度要求照片接口，未触发重连，仍判失败并保留证据，后续改为正常配置和管理接口确认。加强的退出断言要求恢复成功且无停止警告。原生日志中的可选 UsbDk 不存在随后回退 libusb0，不代表本项恢复失败。

## 回归与限制

16 项原生检查通过。实际重连源码使用 Windows API 替身检查精确设备、端口复用、串号失败、PnP 变化、普通权限、过期授权、活动配置、歧义节点以及请求失败不重复。运行时逻辑回归、四语资源和完整本地化审计通过；本地化审计最初发现旧更新记录项目数不一致，保留失败记录后合并同一内容段落并重新通过。

本项没有消除 legacy libusb0 配置初始化对 Apple 驱动的底层影响，而是加入已验证的自动恢复。当前触发条件针对明确的普通配置 3；没有对不确定配置、仍在投屏的接口或无管理员权限强制重置，也没有验证所有硬件、系统版本、企业权限策略和物理 Wi-Fi 漫游。UAC 接受路径已真机通过；取消结果保持失败的控制流与过期请求拒绝已审查，但未把自动化替身测试称为真实 UAC 取消验收。

可运行测试包：`artifacts/iPhoneMirror-usb-reconnect-reviewed/`。原 `iPhoneMirror-usb-inventory-reviewed` 保留为对照；新包仍包含工作区其他既有变更，本专项验证不能代替它们各自的验收。

最终交付核对：包内 App、Core、配置/重连助手与桥接器 SHA-256 均与真机测试宿主一致（`usb-reconnect-artifact-hashes.json`）。836 个 frozen runtime 清单文件及 4 个源码模块比对通过；发布桥接器经生产作业对象启动自检、正常退出，无遗留子进程。两台当前 USB 配置均为 3，Apple 服务均列出；没有遗留测试进程。结构化结果见 `usb-reconnect-review-summary.json`。用户要求本轮结束后暂时停止，已停止继续真机测试，未将完整原任务标为完成。
