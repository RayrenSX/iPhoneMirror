# 用户环境差异补充审查

日期：2026-10-08。本轮接续 [干净环境真机审查](CONTROL_DEVICE_CLEAN_REVIEW.md)，重点检查其他用户环境仍可能触发的失败分支。

## 确认并修复的问题

1. **测速失败被当成来源不可用。** Range/吞吐探测无结果的镜像此前被排除；代理或 CDN 可能拒绝分段请求，但允许完整 GET。现在测量只决定优先级，未测出速度的来源仍留作后备。完整下载仍检查 HTTPS、文件长度、Git blob 和 SHA-256，并遵守总期限。
2. **后续文件重复碰坏来源。** 下载清单时已找到可用镜像，下载镜像和 trustcache 时仍从原来的坏来源开始，可能再次耗费每次最多 45 秒。现在同一阶段中完成校验下载的来源优先用于剩余文件，失败仍可继续尝试其他来源。
3. **无线初始握手重置未进入备用连接。** Network usbmux 已发现设备，但初始 Lockdown 连接重置、断开或连接失败时，原分支未尝试独立的 RemotePairing。现补齐连接异常回退；未信任、密码/锁屏错误仍直接保留，不被另一个连接错误覆盖。有线仍不自动换成无线。
4. **本地缓存失败误导排查。** 创建缓存父目录、临时目录、重命名或写元数据失败时，可能返回原始异常；下载期间磁盘空间或写入权限问题可能被归为网络下载失败。现在返回已有的 `developer_image_cache_failed`，复用四种语言的空间/权限处理建议；明确的磁盘写入错误立即结束，不浪费镜像重试。请求库及 HTTP 流异常仍归入下载错误。

这些问题可以让部分用户仍看到“无法使用反向控制”，但不能据此推定所有历史用户日志都由这些新增问题引起。

## 验证边界与环境条件

- 本轮不再清除设备缓存、信任或配对记录；此前的无缓存下载、真实 Apple 签名与故障注入结果见前一份报告。
- 单元测试验证新回退分支。当前网络此前未发现 RemotePairing mDNS 服务，因此不能将分支测试表述为 RemotePairing 真机连接成功。
- Apple 驱动/服务、信任关系、解锁与开发者模式仍是必要条件；无线还受防火墙、VPN 路由、AP 客户端隔离和服务发现影响。DDI 下载与 Apple 签名需要实际可达的服务器，本地缓存需要可写空间。
- 某些系统或设备可能不提供可用 HID 触控服务；上一轮此设备 Legacy HID 实际返回 RST_STREAM，不能承诺所有设备均有可用后备。
- 有限设备与故障注入覆盖不能证明所有用户环境“无错误”；结论只覆盖记录的测试及可复现修复。
