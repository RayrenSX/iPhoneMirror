# AirPlayServer 上游移植评估（2026-10-09）

## 已完成的移植

根据用户授权，已实现下面评估中除**音频时钟闭环补偿**以外的推荐内容，并额外完成 FDK AAC → FFmpeg 原生 AAC-ELD 迁移。基础版本仍固定在 v1.1.2；新增的第十个源码补丁适配 v1.2.5 的改进，保留本项目现有的 DLL 回调 ABI、FFmpeg 58 ABI、ALAC 协商、音频重传/抖动等待/丢包静音、旋转参数集合并、稳定身份、网络绑定及 URL/HLS 控制。

- 参数包：检查 AVC 配置记录内所有 SPS/PPS 的大端长度与边界，支持多个参数集；错误包丢弃。保留 64 MiB 视频载荷上限和同 NTP 时间戳的参数集/IDR 合并。
- 计时：修正纳秒、微秒倍率；Windows 定时等待扣除当前毫秒并释放等待锁；镜像/音频计时接收使用有符号返回值、48/32 字节最低长度、300 ms 接收窗口及可唤醒的 3 秒探测间隔。
- 音频：拒绝仅 RTP 头的数据及短控制包；停止支持空指针和重复调用，关闭的套接字重置；保留实际 PCM 采样数和采样率。
- 本地音频复审：重复 SETUP 返回当前有效端口；数据和控制 UDP 核对控制会话的远端 IP，忽略其他地址的报文；在首个控制包前使用协商的重传端点。原始包和重传包统一出队，最后一个控制重传包无需等待后续数据包即可输出。FLUSH 清除旧 AAC/ALAC 解码和补静音格式，并发 stop/destroy 等待在途回调退出再释放资源。
- 本地视频复审：FFmpeg 拒绝送包并返回 EAGAIN 时，排空已排队帧后重送同一 access unit；关闭解码器时复位状态，后续帧可以重新初始化。送入 FFmpeg 的数据使用带零填充尾部的自有 AVPacket；限制解码平面总大小并检查像素格式、stride 和尺寸。缩放使用按源/目标尺寸缓存的转换器、向上取整的色度尺寸及失败检查，避免奇数/最小尺寸色度平面长度错误。
- 连接：仅接纳当前控制会话的远端 IP；TCP FIN、接收失败或截断包后保留监听器，最多等待 120 秒重接，包括发送端已暂停的情况。静态/暂停画面没有空闲超时，开始读取但未读完的包有 3 秒期限。重接清理待合并参数和 PTS 基准，保留协商的 AES 上下文；修正跨包 CTR 剩余字节不足时的越界问题。
- 审查后修复：已知完整帧头的加密载荷中断时，按声明的完整帧长度推进 CTR，避免后续帧密码流失步。连续 3 个解密帧无法通过 NAL 边界检查时结束旧流并允许重新 SETUP。同一 streamConnectionID 的 SETUP 重试保持密码流和有效端口；新 ID 先完成旧工作线程及异常停止，再初始化新密钥和监听端口。

## 1. 视频参数包校验：最值得移植

来源：[09f3d82](https://github.com/xenos1337/AirPlayServer/commit/09f3d82bc1576985d9f092bcd092726361b30f59)。建议取其 `raop_rtp_mirror.c` 的参数包校验部分，结合最终 v1.2.5 实现。

重建后的本地源码 `AirPlayServerLib/lib/raop_rtp_mirror.c:582` 起，分配并读取 payload 后，直接访问 `payload[0..7]`，没有先验证最小长度。随后把 SPS 长度存入有符号 `short`，直接 `malloc`、`memcpy`，又用未经验证的 SPS 长度定位 PPS。`lengthofPPS` 的表达式没有按两个字节的大端格式读取长度，而是使用掩码和加法。这些路径可能造成越界读取、错误大小的分配、空指针使用或接收器崩溃。

上游增加最小包长、SPS/PPS 偏移范围、非零长度和分配结果检查，将长度改为 `size_t`，并正确读取 PPS 的 16 位长度。错误参数包可以丢弃，而不必立即结束整个会话。

移植边界：

- 保留本项目的 `pending_sps_pps`：按同一 NTP 时间戳把新参数集与第一帧 IDR 合成 access unit。上游最终版本仍会单独发布参数集，直接覆盖会丢失本项目的旋转修复。
- 本地已经检查加密帧的 NAL 长度，并丢弃不完整 access unit；不要把这部分重复记为新增收益。
- 上游将单包上限改为 8 MiB，本地目前为 64 MiB。建议另行确定分配上限，并用最大分辨率关键帧验证；长度校验的移植无需同时照搬 8 MiB 限制。
- 不直接移入上游整段接收循环：那里还混有重连、暂停和接口变更。

建议验收：截断参数包、零 SPS/PPS、SPS 超出 payload、有符号长度边界、PPS 长度高字节非零、分配失败；随后发送合法参数包确认会话仍可用。有效内容回归覆盖横竖屏切换及最高分辨率。

## 2. 时钟换算：明确缺失且成本低

来源：[58f25272](https://github.com/xenos1337/AirPlayServer/commit/58f252720a6fed49f3e9a344491956ab1f1f33bb)。只需取 `byteutils.c` 的两个单位修复。

本地重建源码仍为：

```c
tv->tv_nsec = t.QuadPart % 1000000;
return (uint64_t)time.tv_sec * 10000000L + (uint64_t)(time.tv_nsec / 1000);
```

第一处把微秒余数放进纳秒字段，第二处把秒换算成了每秒一千万“微秒”。按现有公式计算，底层计时从 999999 微秒变为 1000000 微秒时，`now_us()` 从 999 变为 10000000：实际经过 1 微秒，输出却跳过 9999001 微秒。这是公式推导，不是实机测量。

上游对应为余数乘 1000、秒乘 1000000。本地音频和镜像 timing 线程都会调用 `now_us()`，因此这不是无用函数修复。建议优先补齐，并验证跨秒边界的单调性和时间差。

这个提交也包含视频读取循环改动，其中不少功能已由本项目现有补丁完成。不要整提交覆盖。

## 3. 等待期限和 timing 线程：改善长会话与慢网络

来源：[20c583da](https://github.com/xenos1337/AirPlayServer/commit/20c583da6d0c9b3197eca3f4d4af97d615e147ec)。

本地 Windows `compat.c` 的绝对期限换算只减去当前整秒，没有减掉当前毫秒，可能多等待接近一秒；过期期限还可能转换为很大的无符号等待值。上游使用 64 位中间结果、减去当前毫秒并钳制结果。适合独立回移植，但仍需遵守当前 Windows 条件变量封装的锁和唤醒方式。

本地镜像 timing 线程在 1 毫秒 `select` 超时后休眠 10 毫秒并重新发送请求。手机繁忙或网络较慢时会高频重试。它还使用无符号接收长度，并且未先验证报文长度就读取 NTP 字段。

上游将该控制流量改为 300 毫秒响应窗口、约 3 秒探测间隔，并用有符号返回值和最小 48 字节检查过滤接收失败及短包。它不在视频解码热路径上，较合理的探测间隔不会直接增加视频每帧等待时间。

建议把等待期限、短报文检查和探测节奏作为同一批次；音频 timing 线程的同类接收检查应一并审核。不要把这些改动宣称为端到端音画同步已经解决。

## 4. 音频路由切换与停止：移植小修，保留本地增强

来源：[6f23c01d](https://github.com/xenos1337/AirPlayServer/commit/6f23c01d97667135138e54e993c5d7e8027af6f4)，以及 `09f3d82` 的有效 PCM 检查。

本地仍接受 `packetlen >= 12`。12 字节只有 RTP 头；音频路由变化时发送端可能发这种无载荷标记。上游改为 `> 12`，避免空 access unit 进入 AAC 解码。音频停止时的空指针保护、关闭后将 `csock/tsock/dsock` 设为无效，也值得补齐。本地镜像停止已经有较完整的 `stop_in_progress` 处理，不必按上游标题把整个停止流程重写。

本项目已具备：

- ALAC 与 AAC-ELD 区分，并读取协商的 `ct` 和 `controlPort`。
- 解码失败不发布有效 PCM，以及主机和核心侧的格式校验。
- RTP 重传、抖动等待，以及按已知 PCM 帧长度补静音。

上游 `09f3d82` 的新增有效 PCM 过滤与上述功能部分重叠；可以补充每次出队前清零输出、采样率和声道范围检查，但不能覆盖本地补偿路径。v1.2.5 的音频循环仍使用 `no_resend = 1`，直接覆盖会关闭本项目已经恢复的重传行为。

建议验收：音频输出路由切换、纯 RTP 头、重复 TEARDOWN、无音频流的停止、AAC 解码失败、ALAC 音乐及丢包重传。

## 5. 数据连接重接：收益明显，状态策略需要适配

来源：`09f3d82` 的传输恢复，并参考最终 v1.2.5。

本地已经有精确读取、3 秒分段读取超时、TCP keepalive 和异常退出保护，因此“避免半包永久阻塞”大部分已经覆盖。尚缺的是：手机在控制会话仍有效时关闭并重建镜像数据 TCP 连接，本地会走异常停止；上游保留监听器、清除旧数据连接状态，然后等待新的数据连接。

这对手机 VPN/网络路径变化、临时断流和发送端重建数据连接有实际价值。它应作为独立状态机改动，验证重接后的加密状态、时间戳基准、缓存 SPS/PPS、解码器和设备身份都一致。

需要调整上游策略：

- 最终 v1.2.5 使用 120 秒重连窗口；早期 `09f3d82` 是 15 秒。不要只读早期提交就按 15 秒描述最终版本。
- 上游在 `sender_paused` 时取消重连期限。对于暂停后又发生 TCP 断开的情况，可能长期保留旧会话。`013a220` 虽然名为暂停断流恢复，实际上只改 MirrorSimAdapter 的事件处理，没有修改这段底层期限策略。
- 本项目应区分“连接仍在且主动暂停”“连接丢失”“合法静态画面”。不要根据帧到达间隔直接断开正常静态投屏。
- 建议使用可控的重连窗口和清晰的断流状态；重连接受不能把另一设备串入旧会话。

建议验收：包头中断、payload 中断、FIN/RST、数据连接重接、暂停后断开、正常静态画面、手机 VPN 开关、连续横竖屏切换及多设备交替连接。

## 6. 有价值但应另行设计的内容

### 视频状态和画面几何

[d7f77cb3](https://github.com/xenos1337/AirPlayServer/commit/d7f77cb3b59a36a3afd58df97d965b6b268cb3be) 增加画面几何和发送端暂停回调，有助于准确展示状态。它也将镜像流 socket 类型改为 Windows 的 `SOCKET`，可针对本地接受连接和读取 helper 的 `int` 类型做一次一致性修正；上游本身并未把所有旧 socket 字段都统一改完。

状态事件需要本项目自己的 WirelessHost 回调和命名管道 IPC 支持，不应引入 MirrorSimAdapter 的 JSONL 0.8 协议。若扩展 IPC，应同步版本、两端结构与测试。几何事件也不能替代当前依据解码画面处理旋转的路径。

### 音频设备时钟补偿

[b1cd2bb9](https://github.com/xenos1337/AirPlayServer/commit/b1cd2bb9303a0abf3b3b63cbc02465b04e48a27f) 只修改 `AirPlayServer/CSDLPlayer.cpp` 和 `.h`，通过队列深度调节重采样比例，并保留分数样本余数。

本项目无线音频经 `WirelessClientStream` 进入 `WasapiRenderer`，不使用这个播放器。当前 WASAPI 路径有网络启动缓冲、队列高水位控制、丢帧和重缓冲，未发现自适应速率补偿。因此思路有价值，但复制 SDL 代码没有效果。

若长时间播放确有持续漂移、周期性重缓冲或丢帧，再基于样本帧数、设备消耗和有界重采样实现反馈。不要照搬上游按“包数量”计的目标队列或最大 0.5% 修正，也要覆盖名义采样率相同但物理时钟不同的情况。验收应包含长时播放和队列/丢帧统计。

### AAC 从 FDK 改为 FFmpeg

[7b6fc680](https://github.com/xenos1337/AirPlayServer/commit/7b6fc680a0f479233b93aac302c56f47e4c96d0f) 有减少 FDK 依赖、统一音频解码实现的潜在价值，但成本较高。

上游采用较新的 FFmpeg 通道布局 API。当前接收器固定 avcodec 58 / avutil 56，精简构建只启用 H.264、ALAC，未启用 AAC。不能仅复制 decoder 源码；需要调整 FFmpeg 配方/ABI、验证 AAC-ELD，并保留本项目 ALAC 分流。上游最终 `raop_buffer.c` 使用固定 AAC-ELD 配置，并不具备本项目当前的协商 ALAC 解码路径。

这应单独立项，不能与本次小补丁绑在一起。更新后还需同步依赖清单、来源说明与运行时哈希。

## 不建议当前移植的内容

| 内容 | 原因 |
| --- | --- |
| `8a159ab` 的网卡/MAC 策略整套替换 | 上游选择主网卡 MAC，并简化为一组 DNS-SD 注册。其注册仍用接口 0，不是强制只在主网卡广播。本项目已有虚拟网卡筛选、稳定身份、重复注册合并、全接口广播和控制连接地址绑定；不要据提交标题替换这些策略。可借鉴枚举结果检查。 |

| `f8fe361` 的配对指纹/headless 整套 | 大部分服务于 MirrorSimAdapter 的信任状态和压缩帧输出，涉及新增回调。当前自用镜像收益低于输入校验；公共局域网接收权限应另做产品设计。 |
| MirrorSimAdapter 的音量与 JSONL 协议 | 本项目已经将手机音量通过 `MediaVolume` 传给 WASAPI；新增适配器没有必要。 |
| `8e23e91` 分辨率配置整套 | 本项目已经有运行时分辨率、帧率和配套能力响应，覆盖应用提供的选项。 |
| PIN UI、隐私窗口、PiP、自动全屏、上游 SDL/UI 功能 | 属于上游桌面程序，本项目使用自己的 WPF UI 和媒体路径。 |

## 为什么不能直接换成新版 DLL

当前 `WirelessHost.cpp` 通过固定 MSVC 导出符号查找四参数 `fgServerStart`，并自行声明八项虚函数的 `IAirServerCallback`。新版普通 `fgServerStart` 增加 password 参数，回调插入 `outputH264AccessUnit`、几何和暂停事件及配对审批；导出符号和虚表布局都已经变化。即使改了入口名称，原回调对象也不能按新版布局使用。

完整迁移还会影响本项目的 ALAC、URL/HLS 媒体控制、每设备 IPC 身份、DNS-SD 能力一致性、媒体 socket 地址绑定和旋转 access unit 合并。继续在现有基础上按函数回移植能把回归范围控制在对应功能内。

## 推荐实施批次和验收

第一批：SPS/PPS 校验、PPS 长度读取、两处时钟单位修复、Windows 等待期限、timing 短包检查与发送节奏、RTP 无载荷过滤、音频停止清理。保留现有 ABI、音频解码与旋转路径。

第二批：控制会话内的数据 TCP 重接、暂停/断流状态，以及必要的本项目 IPC 事件。参数包安全检查与重连策略应分开验收，以便定位回归。

后续按需求：WASAPI 长时漂移补偿、FFmpeg AAC-ELD 迁移、局域网配对权限。

落实补丁时应加入固定源码构建配方，重建 DLL，并同步 `SOURCE.md`、`SHA256SUMS.txt` 和应用运行时完整性记录。现有 `WirelessReceiverProtocolSmoke` 可作为协议回归基础，但需要新增参数包边界、断流重接与音频路由场景。源码编译和协议探针通过后，还需分别验证手机镜像、音频、媒体投屏、旋转及多设备，才能将候选 DLL 标为可交付。
