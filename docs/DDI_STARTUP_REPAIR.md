# DDI 启动卡住修复（2026-10-07）

## 已确认的问题

用户日志在 `mounting_developer_image` 后等待 360 秒，最终由主程序超时。
日志无法证明该次现场具体停在哪个子操作，但代码中存在可复现的卡死机制：
固定依赖 pymobiledevice3 11.3.1 的 `TSSRequest.send_receive()` 使用没有网络超时的
`requests.post()`，同时在 `ThreadPoolExecutor` 上使用同步上下文管理器。
取消协程时，退出该上下文会等待 HTTP 线程结束，阻塞桥接器事件循环。
原来只包住 `mount()` 的 `asyncio.wait_for()` 因而无法保证及时返回；
服务打开、关闭和挂载结果查询也没有完整的时间限制。

## 修复行为

- `tools/ddi_support.py` 保留固定版本的 DDI 身份选择和 RestoreRequestRules，
  使用 httpx 异步请求替换签名 HTTP 传输。回归测试对比上游生成的签名参数。
- 保留上游 Apple TSS 入口，不增加镜像或第三方签名服务。
  本次无设备标识的网络检查中，原 HTTP 入口正常返回 TSS 协议响应；
  HTTPS 入口证书验证失败，因此没有更换协议或关闭证书验证。
- 设备已有签名时继续复用；没有签名时才访问 Apple。
- 网络签名超时、服务超时、传输超时直接返回准确错误，避免把网络故障当成镜像损坏重复下载。
  Apple 拒绝旧镜像或镜像不兼容时仍允许尝试下一候选镜像。
- 修复下载候选路径将 `AlreadyMountedError` 和开发者模式关闭误归类为普通挂载失败的问题。
- 检查、签名、传输、激活、验证分别发出状态事件，主程序四种语言同步显示阶段和恢复建议。
- 取消下载后通知后台工作线程，阻止继续尝试下载源及发布缓存文件。
  已在进行的同步 HTTP 读取由原有读超时约束，不宣称能立即杀死线程。
- 主程序保持原有 360 秒兜底；桥接器正常提前返回具体错误码。
  兜底触发时也按最后阶段分类，不再一律显示“无法识别的错误”。

## 再次审查补充

- Apple 临时错误（HTTP 408/429/5xx、TSS 93）和网络传输故障最多尝试两次，
  两次共用原有 40 秒预算。签名拒绝与服务暂时不可用分别提示。
- 设备锁定、未信任、断线、开发者模式查询失败、镜像服务不可用、上传失败与挂载结果未确认，
  保留各自错误码和恢复建议。查询失败不再提示用户一定未开启开发者模式。
- 无论普通挂载还是设备返回 AlreadyMounted，均重新查询镜像状态。
  本地镜像不兼容时切换下一候选；网络或设备故障不再触发无效的镜像下载。
- 启动阶段也监听主程序关闭输入管道，取消挂载并进入清理，减少等待强制终止造成的 USB 重连竞争。
  后续全链路审查改为独立读取与有界队列，恢复会话时不会产生两个线程争抢同一输入，
  已排队的旧指令也不会遮挡输入管道关闭事件。
  仍保留主程序 8 秒强制退出兜底，同步下载中的网络读取仍受其读超时约束。
- 畸形 XML 镜像清单现在进入明确的损坏处理；缓存清单不再依赖元数据排列顺序，且拒绝重复条目。
- 退出、清理和警告事件不再覆盖真实失败诊断；主程序超时也优先显示桥接器已经给出的具体原因。
- 补全四语言恢复提示，未知的规范错误码会显示在提示中，便于用户反馈。

## 全链路复审（2026-10-07）

本轮覆盖主程序校验与启动、输入管道、DDI、USB/RemotePairing 隧道、HID 就绪、
空闲健康检查、断线恢复、退出和再次启动。新增修复：

- 输入读取使用单个后台线程读取原始管道，避免默认执行器在退出时等待阻塞的 stdin，
  也避免 Python BufferedReader 锁导致解释器退出崩溃。读取与 HID 消费解耦，
  最多缓存 1024 条 / 8 MiB；超限和非法 JSON 结构发出明确协议错误。
- RemotePairing 使用与 USB 一致的 45 秒就绪期限和底层隧道监测；ready 之后不限制正常使用时长。
  USB 转 RemotePairing 时，前一个隧道期限不会继续覆盖后续发现、DDI 恢复与重新建连。
- 两种连接均执行空闲 HID 检查。无线故障交给主程序重新发现无线设备，
  不再调用内部固定使用 USB 的重连路径；无线发送失败不再无声返回成功。
- 隧道关闭、Lockdown 关闭、可选无线配对清理都有期限。SDK 读取任务报错后，
  仍释放 userspace 网络栈，保留原始故障。
- 镜像清单补充查询遇到设备断线，不再忽略异常并沿用过期的“已挂载”结果。
- 主程序再次启动时重建取消令牌，忽略旧进程迟到的退出回调；已取消的启动不创建进程。
- 补齐控制服务就绪超时、恢复耗尽及输入协议错误提示；USB 恢复耗尽使用本地化处理建议和重试入口。

新增测试包含真实 Windows 管道子进程测试（父进程保持 stdin 打开时，启动失败仍能退出），
以及 C# 实际创建子进程的启动、停止、复用与旧退出回调隔离测试。
本轮完整 Python 回归 229 项通过；启动错误映射 60 个案例、实际子进程生命周期测试、
应用逻辑测试及四语言检查均通过。
全链路版本输出至 `artifacts/iPhoneMirror-full-chain-reviewed/`。
最终发布目录通过桥接器自检、C# 运行时完整性校验和清单逐文件校验，
打包桥接器与本次源码构建的 SHA-256 一致。
使用不存在的测试设备标识启动打包桥接器后关闭输入，进程在约 1.05 秒内正常退出（退出码 0），
未使用主程序的 8 秒强制结束兜底。该测试只验证退出路径，不代表真机挂载成功。

## HID 与 DDI 来源回退修复（2026-10-07）

- Modern HID 连接成功但没有触控接口 257 时继续尝试 Legacy；候选连接超时也可切换。
  失败或取消时关闭候选，避免键盘接口状态泄漏到下一来源。
- 可选媒体会话失败后保留已验证的直接 HID 认证状态。识别上游媒体认证超时，
  以及 HID 已可用时的 9021，释放失败的媒体连接后走直接控制。
  ready 前仍发送无害释放报告并查询同一 HID，避免仅凭服务名宣布可用。
- RSD 快照没有 Modern/Legacy 端点时，直接交给外层重建服务发现，不在原快照上重复查询三次。
- 默认 DDI 固定到与运行时 27A5228h 匹配的提交
  `6eae353ae694bda1c421d4a3eee5459ae59c99a1`，无需先访问 GitHub 元数据 API。
  显式版本或刷新需要 API 时，故障可回退到固定的兼容元数据。
- 下载顺序为直连、代理、镜像站；直连显式排除环境与系统代理。
  直连与代理各共享 20 秒尝试预算，活跃文件传输仍可在整体下载期限内完成，

- 先下载并校验 BuildManifest，再下载大镜像；远端版本不兼容时回退固定版本。

  缓存镜像被明确拒绝时记录其具体内容；最多检查一次不同的兼容版本，

## 来源修复后的再次复审（2026-10-07）

本次复审发现并修正以下遗漏：

- 重连时 `_recovering` 原本会禁止可选媒体/HID 回退，使首次启动可用的设备在断线后恢复失败。
  改为判断本次会话是否已经完成 ready；重连启动仍允许回退，已建立会话的故障继续交给恢复监督器。
- SDK 的媒体会话在 startmediastream 失败时未释放接收器，停止与关闭服务也没有期限。
  桥接器现在按相同的媒体认证顺序自行管理会话，在部分打开、认证失败、取消及正常退出时清理资源，
  限制服务打开和关闭时间，并保留原始异常。
- 缓存的拒绝记录原本是全局且永久的，可能跨设备阻断可用镜像。
  现在以设备标识、系统版本和构建号的哈希区分，五分钟后失效；不存储明文设备标识。
  同一轮仍只刷新一次，其他设备以及过期后的显式重试可以再次尝试原镜像。
- 缓存元数据允许无序排列，但拒绝内容比较曾依赖排列顺序。读取时统一到固定文件顺序，
  避免相同内容因元数据顺序不同绕过拒绝检查。
- 元数据查询改为有大小限制的流式读取，直连与代理共享 25 秒预算；元数据、下载和不兼容版本回退
  共同受 150 秒下载期限约束。总时间耗尽立即报下载超时，不继续测速、尝试来源或发布缓存。

真实 GitHub 元数据查询约 7.90 秒完成，三个文件的 blob 与长度均匹配固定版本。
