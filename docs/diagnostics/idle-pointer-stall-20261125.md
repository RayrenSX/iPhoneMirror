# 空闲时周期性鼠标卡顿：核心环境检测锁竞争

## 反馈与已确认的问题

用户反馈：未连接手机、未投屏，仅打开程序时，移动鼠标约每五秒停顿约 0.2 秒。

主窗口刷新定时器间隔为两秒。没有投屏会话时，每次刷新都读取环境和有线库存。
`im_get_environment` 原先在整个服务状态、PnP 和本地 TCP 端口查询期间持有 `state_mutex`。
界面线程每 250 毫秒调用的接收器状态查询也需要这把锁。因此环境检测即使在
`Task.Run` 中执行，也会通过共享锁阻塞界面。若配置了鼠标设置快捷键，主线程上的
`WH_MOUSE_LL` 回调还会让界面停顿影响全局鼠标事件的传递。

本机独立核心探针复现了这一锁竞争，未启动接收器或投屏。探针库存有一条有线设备，
所以这不是对反馈者“没有连接手机”条件的完整实机复现。

## 审查后的最终修改

- `im_get_environment` 只在检查初始化状态时短暂持有 `state_mutex`，慢查询在锁外执行。
  使用共享 `initialization_mutex` 保证查询完成前核心不会关闭，与设备枚举的生命周期约定一致。
  环境查询只读取服务、设备树和运行库元信息，不进入 USB 采集后端或改变驱动状态。
- 保留原来的两秒空闲设备检测。上一版加入的空库存 30 秒兜底及插拔消息调度已全部撤回：
  Apple 服务恢复和漏通知场景可能延迟设备发现，不能用这种响应退化换取空闲性能。
  设备库存、手动刷新、自动发现、USB 恢复及托盘检测均沿用原流程。
- 非阻塞本地 TCP 连接同时监听 Winsock 的写就绪和异常集合，正确报告拒绝连接。
  Windows 的 SYN 重试策略仍可能让短时间探测等到原有的 250 毫秒超时；此修改没有被计作
  本机环境检测耗时下降。界面响应的改善来自移除核心全局锁竞争。

本次生产代码最终仅修改核心环境查询的锁范围和本地 Socket 连接错误检测。
未修改 iUsbBridge；未停止或覆盖 `outputs/iPhoneMirror-main` 中正在运行的实例。

## 测量

同一工作树原生 Release DLL，修改前 10 次、首次修改后 20 次；单位毫秒：

| 指标 | 修改前中位数 / 最长 | 首次修改后中位数 / 最长 |
|---|---:|---:|
| 环境检测 | 267.920 / 284.548 | 267.636 / 281.015 |
| 有线库存枚举 | 281.745 / 296.965 | 267.920 / 283.615 |
| 与环境检测并发的媒体接收器状态查询 | 259.404 / 280.527 | 0.013 / 0.202 |

审查后再次测量 20 次，并把状态采样加强为每次依次查询媒体和无线接收器：

| 指标 | 中位数 / 最长（毫秒） |
|---|---:|
| 环境检测 | 267.638 / 280.704 |
| 有线库存枚举 | 275.878 / 295.543 |
| 并发查询两个接收器状态（343 组） | 0.023 / 0.076 |

测量针对界面调用等待时间，未直接测量鼠标事件延迟或系统 DPC；反馈者机器上的最终体验仍需复测。

