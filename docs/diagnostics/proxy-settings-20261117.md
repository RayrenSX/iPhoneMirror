# 应用内网络代理设置

将此前通过 `Start-With-Proxy.cmd` 设置进程环境的代理能力，加入现有“应用”设置分类。三个设置分类保持不变，网络代理独立显示，不增加折叠层级。

模式为默认网络设置、不使用代理、手动 HTTP 代理。手动地址可填写 `http://127.0.0.1:7897`，也接受主机和端口形式并规范化；不支持在地址中保存用户名、密码、路径或查询。设置持久化、复制和旧配置迁移均使用独立的代理选项。保存失败恢复原配置，非法地址不保存。

保存后重启应用生效，避免改变正在播放的视频或下载。只改变本应用进程的代理环境与 .NET 网络策略，不修改 Windows 系统代理。默认模式保留原有环境和组件默认行为；不使用代理模式清除继承的代理并为应用 HTTP 客户端指定直连；手动模式使用指定 HTTP 代理。localhost、127.0.0.1 和 ::1 的本机服务请求保持旁路。

FFmpeg 投屏和音频解码子进程继承已应用的代理环境。FCUP Broker 继续提供本地服务，不增加公网下载路径。更新和应用下载使用 .NET 默认代理。普通 MP4 的 WPF 播放器缺少独立代理接口，显式代理模式下由本地随机令牌中继转发原始媒体字节和 Range 请求；不重新编码，保持原生播放器的播放和定位行为。重播、失败和停止分别复用、重建或释放该中继。

代理地址、签名媒体地址和请求内容不写入新增诊断。中继仅允许绑定的令牌路径及 GET/HEAD，有限重定向只允许 HTTP(S)，关闭时取消请求与监听。界面明确显示重启说明。

验证包含设置保存/加载/失败回滚、多语言窄宽布局、真实 HTTP 代理命中与本地旁路、直连模式、子进程环境、原字节 Range/HEAD/416、重定向、取消，以及真实 WPF 代理播放。通过结果和交付哈希以本次 `BUILD-INFO.json` 为准。

本次应用与 Runtime Release 构建零警告、零错误。完整 Logic、策略专项和 HTTP 中继专项通过。设置 Runtime 专项验证三模式、地址拒绝、磁盘往返、深复制、保存失败回滚、重新打开、保存不影响当前生效策略；四张中英窄宽截图经过查看，代理卡片和提示完整可见。

实际 WPF 从无法直接解析的测试域名，经本地 HTTP 代理播放 MP4、完成后重播，再播放本机来源：实际末尾位置分别 3.220、3.196、3.217 秒，首尾画面变化，零停止投屏请求。前两项经过本地随机路径中继，第三项绕过代理，代理请求计数保持不变。测试没有改写用户真实设置或操作手机。

界面路径为“应用 → 网络代理”。选择“手动 HTTP 代理”，填写地址并保存，退出后普通启动即可使用。交付不再提供设置代理环境的专用启动器；历史交付保持原样。
