# 托盘启动后设置页空白（2026-11-15）

## 复现与原因

使用真实 WPF 主窗口执行 `StartInTray`，保持主窗口未显示且未触发 `Loaded`，再从托盘面板切换到轻量模式。全过程不连接设备、不启动投屏，打开设置并选择“应用”后复现用户截图：标签的 `IsChecked=True`，对应 `ScrollViewer.Visibility=Collapsed`，尺寸、视口高度和内容高度均为 0。

三页设置原来通过样式中的 `DataTrigger` 和 `ElementName` 绑定标签选中状态。在上述隐藏 HWND 初始化路径下，选中标签后页面仍保持折叠。修复后直接用实际标签对象作为三个可见性绑定的 `Source`，在 XAML 初始化完成后建立绑定，再恢复保存的分类，不依赖窗口曾经显示或投屏状态。仍保留应用、投屏、反控三个分类及原有设置内容。

## 验证

新增 `--tray-startup-settings` 回归，修复前在用户路径稳定失败，修复后通过全部 12 组组合：深浅主题 × 首次切换到轻量/完整模式 × 三种保存的分类。

每组检查保存的分类首次显示、逐一切换三页、关闭重开设置、往返托盘后重新显示。检查页面实际尺寸、视口、内容、可见控件和数据上下文，确认其他两页折叠，没有重叠。全过程无设备、无投屏，绑定诊断 0 条。保存了 36 张分类截图，已检查轻量模式应用、投屏、反控页面的渲染。

原有 `--settings-categories` 回归通过：分类保存/加载、重开保留分类和滚动位置、设置下拉选择、失败保存回滚、设备独立方向/灵敏度、悬浮设置同步，以及五种语言的深浅主题布局。

`--tray-mode` 综合回归也通过，覆盖隐藏启动、托盘面板、窗口隐藏/恢复、模式切换、音频偏好、媒体停止通知及映射草稿保留。该测试原先将前一个悬浮设置用例留下的离线偏好记录当作新投屏状态，导致前置断言失败；现在先确认记录没有捕获句柄、没有启动/停止任务，再移除测试设备的离线记录，确保“首次投屏”测试独立。没有因此修改音频产品逻辑。

复现和测试产物位于 `outputs/diagnostics/tray-startup-settings/`。`repro-bindings/` 保留修复前的空白截图，`final/` 保留修复后的截图及空的绑定诊断文件；测试使用隔离的配置文件，不改用户设置。
