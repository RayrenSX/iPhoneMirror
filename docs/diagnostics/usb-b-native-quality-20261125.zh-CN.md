# 有线 B 模式 iPhone 原生画质修复

## 问题与修复

同一台 iPhone 17（iPhone18,3）在 2026-11-25 16:13 的有线 B 会话中，请求为 `2622×2622`，手机实际编码、解码和显示均为 `662×1440`。16:15 的 A 会话编码和输出均为 `1206×2622`。本地渲染限制为 `0×0`，因此低清来自源端协商。

原实现仅在 iPad 上启用原生 presentation 协商；iPhone 一直使用普通非 Valeria 协商。修复后，iPhone 和 iPad 的 B 模式均在确认随附 AVC 4:4:4 解码器和实时 SpringBoard 方向服务可用后，启用 `Stevenote` 与 `H264DecoderSupports444`，默认声明 `4096×4096` 的对称显示能力。这个尺寸是接收能力范围，不是把源画面放大至 4096，也不是输出分辨率。Valeria 保持关闭，保留真实状态栏。

源帧维持原来的像素尺寸，按接收时记录的系统方向旋转，并沿用现有画面内容识别和渲染链路。重连和显示重协商保留原生能力，不将首帧的低分辨率反馈成新的设备原生尺寸。

B 模式不再因缺少解码器或方向服务而静默退回普通低清协商。缺少完整解码组件报告 `-2110`；方向服务不可用或中断报告 `-2111`，界面显示本地化恢复提示。A/C 模式保持原来的协议选择。此任务没有修改桥接源码或运行时。
