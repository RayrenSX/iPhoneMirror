## 原因与修复

`MainWindow.QueueMediaCastCompletion` 原先只对本地 FCUP 播放列表报告单项 Completed；其它来源的自然结束都请求停止投屏。爱奇艺此次为外部 HLS，走入了停止分支。普通 HTTP MP4 存在相同遗漏。

自然结束统一报告单项 Completed，保留发送端会话，使手机可以发送下一集。桥接 HLS 仍使用实际观察位置检查提前 EOF，并限制为一次恢复；错误和用户停止不报告自然完成。直接 MP4 沿用播放器的自然结束判断。

DLNA 的完成或失败也同步自身的 STOPPED 状态并通知控制端；同步只允许匹配当前项目和传输代次，不能让旧项目或另一条 AirPlay 会话改动新的 DLNA 播放。未新增自动消费 NextURI 的逻辑。
