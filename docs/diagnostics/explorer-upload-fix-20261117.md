# 资源管理器复制进入手机失败修复

用户在 `explorer-mapping-20261117` 确认可以映射浏览且白框消失，随后报告从电脑复制约 3.84 MB 中文 PPTX 到手机失败，Windows 提示无法读源文件或磁盘。本次以该失败反馈为准，前一条“读写正常”不作为上传全面通过。

## 复现与原因

在不接触手机和用户 Z: 映射的独立 Y: 内存文件服务，使用 Windows Shell 复制本地生成的 4,026,532 字节中文 PPTX，明确复现返回错误 31（0x1F）。请求序列为 `PUT 201 → LOCK 200 → PROPPATCH 405 → HEAD 200 → PUT 204 → PROPPATCH 405 → DELETE 204`：内容上传完成，但 Windows 的属性保存请求未被支持，Shell 失败后删除新文件。大小未触及本机 50,000,000 字节上限。

先前测试使用直接文件写入及从映射复制到电脑，遗漏了 Shell 从电脑复制进入映射时附带的属性设置流程。失败证据为 `work/explorer-mapping-20261117/shell-upload-before.log` 和 `shell-upload-trace-before.log`。

## 修复

补齐 Windows 实际使用的 WebDAV `PROPPATCH`，包括创建时间、最后访问时间、修改时间和常见文件属性，按锁及条件检查后提交；无效或不支持的属性整批拒绝，不返回无操作的成功结果。手机文件修改时间通过 AFC 实际保存，Windows 专属的创建／访问时间和普通 Archive／Normal 标记属于当前映射会话的虚拟卷元数据，按手机文件快照绑定，外部更改、覆盖、删除及映射结束时失效，不冒充手机原生属性。不会为此修改 Windows 注册表或传输上限。

增加只记录操作名、HTTP 状态及桥接错误码的诊断，不记录能力路径、文件名、请求头或上传本地路径。用户反馈的开关位置同时整理为文件工具区内的紧凑设置栏，状态、开关与打开入口统一对齐。

## 验证范围

相同的实际 Windows Shell 上传在协议修复后返回 0，无删除回滚；文件大小、SHA、完整回读和原始修改时间一致，测试盘正常卸载。新协议测试验证属性成功、无效属性原子拒绝及原有读写、锁、路径和取消行为。真实手机上传仍需新版实测，不能将隔离内存测试当作手机结果。

补测使用产品 `DeviceHubExplorerFileStore` 适配器而非直接内存文件接口：Windows Shell → WebDAV → 产品适配器 → 内存 JSON Hub。3.84 MiB 中文 PPTX 复制成功，确认 `set_mapped_file_time` 实际穿过适配器两次，协议返回两次 `PROPPATCH 207`、没有回滚删除；内容 SHA、Windows 读回和 Hub 保存的原修改时间均一致。

Release 构建 0 警告、0 错误，完整 App Logic（含 PROPPATCH／元数据缓存／原有读写与锁）通过，映射取消与清理生命周期通过。Python 文件操作与时间专项 17 项、运行时检查 7 项通过；打包后 13 模块、13 功能和 863 文件清单校验通过。五语言、明暗主题及紧凑／简易界面回归通过；已查看新映射栏实际截图，工具栏、映射栏与列表左右边线一致，名称、盘符、打开图标和滑动开关互不重叠。
