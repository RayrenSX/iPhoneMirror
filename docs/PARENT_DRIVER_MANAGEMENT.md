# Apple 父驱动管理

驱动管理器的“高级设置 → 父驱动管理”可对选中的、已连接的 iPhone/iPad 父设备执行：

- 重新绑定 Windows USB Composite Device（usbccgp）。
- 切换到 Windows 为该设备列出的驱动或当前安装的驱动，包括 Apple 官方驱动。
- 重建设备：移除该父设备及子接口，提示重新插拔后由 Windows 重新枚举。驱动包保留，因此可能重新选中原绑定。

不再依据当前服务名称限制父驱动修改；未知服务、空服务、故障代码 10/22/28/31/43 均可进入管理。设备是否连接由正常模式的 CM_Locate_DevNode 判断，DN_STARTED 和问题代码只用于健康判断。

每次修改都有独立确认，显示设备实例、当前驱动、目标驱动及连接影响。快捷安装遇到父驱动异常时同样需要该确认。取消不会发起父驱动操作。确认只适用于这次设备状态和目标选择；客户端及提权进程都验证确认信息，执行前再次核对绑定和过滤器，状态变化时要求重新确认。

绑定使用 SetupAPI 驱动列表和 DiInstallDevice，目标为单个设备实例。usb.inf 使用全局类列表枚举通用复合驱动，再通过 DIOD_INHERIT_CLASSDRVS 将列表附加到该实例，覆盖 Apple 设备缺少 USB\COMPOSITE 匹配项或被错误分配设备类的情况。系统签名检查保持启用。界面提供系统驱动及适用候选项，不提供任意外部 INF 文件导入。

操作前的 JSON 快照保存在 `%ProgramData%\iPhoneMirror.Driver\Backups\parent-<operation-id>.json`，记录原绑定、父设备过滤器、子设备上层过滤器和已确认的目标；操作日志位于同目录树的 `Operations` 下。快照是诊断状态记录，不是完整驱动包或一键还原文件。重新绑定失败时尝试重新安装原驱动；原驱动缺失或恢复无法验证时会明确提示人工恢复。需要重启的操作仅报告 Windows 已接受请求，重启后仍需重新检测。重建设备没有自动还原保证。

验证包括：客户端及提权入口拒绝缺失确认；未知、官方、空服务及常见问题代码；确认后状态变化；快照保存失败；安装部分失败、健康检查失败、原绑定恢复、恢复失败及重启分支；Windows x64 结构布局；真实设备的只读候选驱动枚举；三种语言资源检查。测试不调用真实驱动安装或设备移除。实际绑定及重启后的持久性仍需在可恢复的测试设备上验证。
